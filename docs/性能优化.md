# 性能优化

## 本轮范围

以相同输入、结果、排序、操作次数与保护条件为验收依据，减少无关刷新、地图重复索引/解压、世界数据主进程计算及界面重复计算。优先优化已测得的瓶颈；不降低刷新频率、不减少扫描/日志/导出内容、不延迟业务落盘、不放宽校验和超时、不增加副作用重试。

保留所有已有工作区与业务变更。未保存草稿、撤销历史、配置 revision、会话 generation、进程身份、源文件变化检查和取消处理不得作为性能代价被削弱。版本保持当前本地版本，提交和发布单独按授权执行。

## 实施与验证

- [x] 资源事件去重与按变化刷新，合成进度通知不再反复读取配置和存档。
- [x] 地图索引与解压副本复用；读取前后验证来源，变化失效、取消清理、无常驻数据库句柄。
- [x] 世界数据比较/查询/导出在后台计算，快照和搜索索引有界，输出等价。
- [x] 日志元数据和内容更新分离，模组与字段展示减少重复计算；可丢弃缓存设限。
- [x] 等价性、性能对照、相关 UI 和最终发行包验证（全套服务测试保留下述设备超时限制）。

按需分包和日志虚拟化只有在收益明确且能保持资源加载、文本复制与滚动语义时才引入，不为形式上的优化改写框架。

## 实现与边界

资源监听区分新资源事件、任务状态切换与纯进度更新。相同配置列表复用引用，页面重新进入、真实修改和原有手动刷新仍读取最新状态；保存时的 revision 检查不变。日志内容与会话元数据分开订阅，后台页面不再因每批日志重绘；日志行复用时间及文本渲染，保留现有 DOM、复制、定位、搜索、归档与跟随行为。

地图最多保留一个来源的解压缓存与有界区块键索引。超过 20 万条候选区块键时不保留索引，仍执行原完整读取；这是缓存容量，不是扫描范围限制。目录身份、压缩包身份、数据库文件清单与时间戳在读取前后继续校验，变化后重建索引或要求重新选择。每次读取都会关闭数据库，取消/失败/退出立即清理缓存，空闲 60 秒释放缓存与解压副本。缓存只在任务所属目录内操作，不写来源。

世界数据查询、比较和 JSON/CSV/SVG 文本生成由独立计算 worker 执行，复用最近四份快照与按需构建的搜索索引；主进程只保存来源元数据用于导出位置校验。计算线程异常后会提示重新扫描，不自动重放操作。首次传输快照和后续 IPC 有成本；该优化主要降低主进程停顿，不承诺所有计算的总耗时更短。

世界数据加载由当前存档工作区持有，打开后后台预加载，子页共享同一在途任务。换来源、读取范围或退出工作区先取消旧请求，再启动新任务；只在数据页可见时轮询进度。返回数据页时后台校验来源，目录比较身份及受支持文件的清单/大小/时间戳，归档比较文件身份；命中后跳过 LevelDB/NBT/模组内容解码，归档也不再解压。仍使用最近四份快照，不常驻数据库句柄，不扫描存档库中的其他世界。缓存被淘汰或写入失效时重新读取；取消和失败不触发自动重试。列表摘要只生成简短描述，详细字段在选中对象后才生成。

模组扫描仍检查目录、文件与跨包关系，只复用身份/大小/修改时间均未变化的 JSON 解析及图片结果。缓存最多 256 文件、原文件总大小 8 MiB，返回 JSON 副本以免调用方污染缓存；损坏、替换、修改后重新处理。内容页对搜索文本和包计数只计算一次。界面图片缓存最多 32 条及约 32 MiB 字符串预算，失败不永久缓存。未保存草稿、撤销历史和业务落盘流程不受这些缓存淘汰影响。

## 同输入性能对照

合成场景下，12 份配置、3 个世界，10 次扫描进度通知：配置页从 120 次 project.read 降为 0，存档页从 10 次 worlds.list 降为 0；真实 IPC 修改后的页面刷新继续通过验收。

含 30,000 条无关元数据的基岩夹具，每次只请求一个区块：后续目录读取约从 33–36ms 降为 9ms，压缩包读取约从 43–49ms 降为 7ms；后续请求复用 20 条候选区块键，不再遍历全部记录或重新解压。所有输出与不使用缓存的读取逐项相等。初次读取仍建立索引与解压。

8,000 对象、约 17.4 MiB 快照，预热后五次中位值：

| 操作 | 原同步总耗时 | 后台总耗时 | 原主进程定时器延迟 | 后台主进程定时器延迟 |
|---|---:|---:|---:|---:|
| 对象比较 | 71.8ms | 84.3ms | 72.4ms | 11.5ms |
| 带搜索的首屏查询 | 13.9ms | 0.6ms | 14.0ms | 5.2ms |
| JSON 导出字符串 | 32.3ms | 48.0ms | 32.4ms | 4.6ms |

后台比较和导出增加线程通信成本，但主进程能继续处理事件。首次启动线程并传输两份快照约 95ms，未计入预热后表格。数值仅为本机合成微基准，受系统调度影响，不是游戏 FPS、真实地图耗时或整体性能提升百分比。

## 暂不实施

日志虚拟化、重页面分包和进程发现方式仍保留现有实现：前两者需要分别证明文本选择/滚动和 ASAR/CSP/加载语义等价，后者涉及进程身份与权限保护。本轮已用更新范围隔离和渲染复用处理日志开销，不通过减少日志行或延长刷新间隔获得收益。

## 验证结果

构建通过。全套服务测试 447 项中 446 通过、1 项失败；失败仍是当前设备上已有的 Windows 进程枚举 10 秒超时，本轮未修改该实现、测试或超时，不将全套测试表述为全绿。

新增测试覆盖相关事件刷新、日志订阅范围、目录/压缩包/维度切换的缓存等价性、文件替换、缓存取消/空闲清理、JSON 修改与损坏恢复、后台快照淘汰和导出结果一致。真实 preload/IPC 的性能、工作区、地图像素与选区、配置/存档、日志与归档搜索、双客户端自动化、文件选择和包编辑专项通过。

当前版本本地包已生成，72 个文件的 ZIP 清单及 SHA-256 校验通过，包含独立计算 worker。发行 EXE 的性能、工作区、首次启动、页面入口、配置持久化及无外部 Node/Python PATH 验收通过。检测到旧发行目录正在使用时，新包输出到独立构建目录，保留用户正在运行的实例。测试使用合成数据，没有运行真实游戏或开展异地联机验证。
