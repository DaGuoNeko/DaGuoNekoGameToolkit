# 0.1.16

## 修复

- 修复安装更新时更新启动器的当前目录留在安装目录，Windows 因此拒绝替换该目录，并提示另一个进程正在使用此文件。启动器在运行脚本前改到更新缓存目录，客户端启动它时也指定该目录。
- 修复重启后继续安装已下载更新时，计划中仍记录上次进程号。脚本会以为旧进程已经退出，随即因当前程序仍在运行而失败，并把 PowerShell 错误记录显示为“更新脚本未能启动”。安装前会改写为当前进程号；同一程序的剩余进程在时限内等待退出，而不是立刻失败。
- 替换目录遇到短暂的文件占用时会有限重试。失败结果只在备份目录仍然存在时记录备份路径。

## 验证与范围

- npm.cmd run build 通过。全量服务测试 428/429 通过；剩余 1 项是全量运行时 WMI 进程盘点超过 10 秒，单独复测通过。未放宽产品超时或进程保护。
- 更新安装、更新服务和更新启动器测试 17/17 通过，包括从安装目录启动更新器并完成目录替换。
- 本地发行包包含 70 个文件，ZIP 清单和 SHA-256 校验通过。正式发布通过 v0.1.16 标签触发 GitHub Actions 构建并上传 ZIP、.sha256 和 latest.json。
- 0.1.15 及更早的已安装程序仍使用它自带的更新器。本次修复从 0.1.16 安装之后的下一次更新开始生效。正常双击启动的 0.1.15 直接替换自身目录，仍可能因旧更新器占用目录而失败。
