# 前端业务与用户路径

## 目标

前端不仅安排页面，还要帮助用户完成有目标、有对象、有结果的操作。布局评估统一检查：用户要做什么、当前对象是什么、主要动作是否直接可见、操作影响哪份数据、结果在哪里、失败怎样继续、返回后是否仍是原对象。入口数量变少或外观一致不能单独证明体验更好。

## 参考项目的实际组织

本轮读取的是项目实现，不把项目名或截图当作设计结论。公开仓库与版本范围见 [UI 视觉重构](UI视觉重构.md#工作区交互修正)；ChatLuna 两代来自本机授权源码。

| 参考 | 实际业务关系与实现证据 | 本工具箱采用 | 不直接照搬 |
|---|---|---|---|
| Elysia-Api | 来源提供模型，模型组组织可用模型；`sources/quick-group-dialogs.tsx` 从选中模型预填建组，成功才清选择；`usage-logs.tsx` 接收总览失败记录 ID，`sources.tsx` 接收来源 ID，直接打开目标并消费导航参数 | 从存档直达其绑定配置；明确修改模板影响下次启动，返回仍定位原存档 | API 网关的模型源/组不等于存档/模组，不复制它的数据层级 |

## 业务对象与模块归属

| 模块 | 用户目标 | 主要对象 | 常用入口 | 后续路径 |
|---|---|---|---|---|
| 存档库 | 找到、创建或导入要处理的世界 | 已登记存档 | 导入、新建、打开存档、快速测试 | 存档概览 → 内容/地图/设置，或启动后会话 |
| 外部查看 | 临时检查磁盘世界，不登记或启动 | 授权目录/压缩包 | 打开外部存档 | 地图/世界数据 → 搜索、定位、比较、导出 → 退出查看 |
| 存档工作区 | 管理这个世界并准备运行 | worldId | 页头启动/查看运行，二级地图/数据/模组/设置 | 编辑绑定配置后返回；查看本次运行日志 |
| 模组与资源 | 登记、浏览和编辑资源定义 | 模组目录或来源包 | 全局目录、内容浏览、UI 编辑器 | 配置勾选；存档包浏览留在该存档范围 |
| 启动配置 | 复用玩家、游戏版本、模组与热更新选项 | profileId、草稿 revision | 配置卡片编辑；存档的绑定配置链接 | 保存供下一次启动；返回来源存档，保留未保存草稿 |
| 运行与调试 | 控制和观察一次实际运行 | sessionId、调试登记与代次 | 当前会话选择器、控制台/日志/代码/UI/性能 | 回到该会话关联的存档，不回到无关的浏览焦点 |
| 远程联机 | 邀请异地玩家或加入邀请 | 房间、邀请、角色 | 创建/加入房间 | 房间状态、结束分享；本机测试不走隧道 |
| 任务与记录 | 判断后台操作是否完成、定位失败原因 | 操作任务和工具箱事件 | 进行中、失败与中断、完成历史 | 明确结果和来源；无可靠身份的旧事件只展示证据 |
| 网易全局配置 | 查看网易客户端按身份保存的全局配置 | 玩家 config 或直接 config 目录中的文件 | 工具箱侧栏，任务与记录上方 | 打开或定位文件，不写入、不登记为存档 |
| 设置 | 调整全局默认和工具箱行为 | 全局设置、版本 | 分类设置与游戏启动覆盖 | 显示影响范围和生效时机，不冒充当前会话快照 |

## 重点路径与验收

1. **带地图开始工作**：存档库优先提供导入、新建、外部查看。管理目录为辅助图标；启动多人客户端留在运行工作区，减少列表页重复的全局工具。
2. **存档 → 启动配置 → 存档**：概览显示绑定配置名称，明确进入该 profileId 的编辑页。另一配置有草稿时沿用切换确认；取消仍留在原存档。返回来源存档不擅自保存或丢弃草稿。
3. **存档 → 会话 → 对应存档**：运行上下文是具体启动快照；“打开关联存档”携带 worldId。即使之前查看了别的世界或外部文件，也进入该会话的存档。目标移除后显示不可用，不猜测替代对象。
4. **只读检查**：外部查看没有隐式登记；读取结果携带来源、时间、覆盖、失败与截断。能打开字段不代表能验证剧情或运行结果。
5. **数据 → 地图 → 数据**：按对象的维度/坐标定位，保留对象与搜索状态；未知维度不自动当成主世界。
6. **后台操作 → 结果**：进行中任务始终展示进度，失败/中断单独暴露，已完成/取消记录折叠；错误记录能读取原因，不能把结果不明操作自动重放。
7. **退出工作区**：固定左上方入口表示退出浏览，不能伪装停止游戏。返回后不重新启动、执行命令或修改配置。

## 交互一致性

- 一级导航回答“哪个业务领域”；二级导航回答“这个对象的哪种工作”；按钮执行动作；状态文字表达事实。三者不用相同的强视觉样式争夺注意力。
- 关联入口携带对象 ID，不只打开一个大页面让用户再找一遍。一次性导航请求消费后清除，普通切页继续尊重用户最近浏览位置。
- 卡片动作按频率与风险固定排列，键盘顺序与视觉顺序相同。主要动作不藏在只有少数选项的展开区。
- 相同含义使用同一名称；模组定义、世界实例、模板、运行快照、历史记录不能互相代称。
- 保存、立即执行和下次生效分别说明；已有备份、revision、generation、来源变化和进程检查继续生效。
- 空状态给出能完成当前目标的下一步；失败不显示空列表伪装成功。只显示对该对象有效的操作，不添加不可用的未来功能占位。
- 业务入口变化要测完整往返和异常分支，视觉截图之外还要测鼠标、键盘、状态保持及无副作用。

## 实施范围

保持现有七个业务入口，不再另加项目或路由框架。本轮将以上原则落实到导航方向/标题栏/卡片/退出入口修正，并补充绑定配置往返、会话关联存档定位、任务状态分层和存档库主动作排序。其他未落地的参考机制不列为已实现功能。验证以对应专项测试和当前本地包为准。

## 验证边界

开发构建与当前 0.1.16 发行 EXE 的导航专项通过，覆盖一级正序/逆序、恢复二级页、原生标题栏点击、配置目标准确性、未保存草稿往返、取消切换、固定卡片高度、置顶退出、键盘及两种主题。多主机模拟验收确认“打开关联存档”使用当前会话目标，即使之前浏览的是另一个世界；定向停止与存档回收保护继续通过。活动/共享逻辑及模块边界测试通过。

工作区专项同时检查进行中任务不混入成功记录、失败与中断可见、历史默认折叠且可展开，以及外部读取和导出流程。验证使用合成夹具和真实 preload/IPC；不据此宣称完成真实游戏剧情或异地联机验收。本轮没有调整产品超时或放宽数据/进程保护，没有新增运行依赖、升版或对外发布。
