# 开发计划

本文件记录已经确认、但尚未进入当前正式版本的后续工作。完成计划项时，应把实际改动、测试结果和限制写入对应版本的[开发记录](开发记录.md)与 `docs/releases/<version>.md`。

## 0.1.8 发布内容

### 联机客户端日志保留失败状态

已实现：`DesktopUI/shared/join-status.cjs` 统一结果显示，`logs.jsx` 使用该规则，避免停止后的“已结束”遮住失败原因。

当前显示优先级：

1. `failed` 显示“加入失败”；
2. `needs_attention` / `waiting_assertion` 显示“需要处理”；
3. `joined` 显示“入房已验证”；
4. 没有联机结果时，已停止会话才显示“已结束”。

`tests/engine-profile.test.cjs` 覆盖结果优先级；`tests/local-join-ui.cjs` 通过产品 UI 验证停止后的失败目标和悬停错误详情。

### 多游戏版本联机能力矩阵

已实现：`DesktopUI/electron/supported-engines.json` 统一登记 `3.10.0.420447` 和 `3.10.0.436581` 的 EXE SHA-256、自动入房、独立主机和独立来宾能力。设置和启动配置下拉框显示已安装程序的实际能力；本机来宾锁定房主启动快照，主客机指纹不一致时拒绝启动。MCP 状态及构建时网络助手名单使用同一表。

已完成公共逻辑，剩余验证边界：

- `autoJoin` 汇总原生桥、OreUI、玩家名、发现和入房回执验证；隔离能力需要同时通过内置 MCDK 固定哈希和 Known Folder 桥检查，不另建重复的版本清单；
- `3.10.0.420447` 保留旧版已有自动入房能力，但独立主机/来宾仍为 false；获得该构建后才能补齐同版本实机隔离与联机验证；
- `tests/local-multiplayer-live.cjs` 提供单机双开验收，不需要樱花；实机失败必须如实记录，不用模拟测试替代；
- 冷启动实测定位到固定 10 秒等待早于引擎初始化完成的问题，已改为使用所属进程的引擎启动完成记录放行菜单操作，保留原总超时与单次输入；
- 本轮 `3.10.0.436581` 实机双开入房、房主回执、全局版本变更后的快照匹配、独立目录及定向停止通过；完整服务回归 343/343，详见[开发记录](开发记录.md)；
- 新增版本时必须更新 `supported-engines.json`、能力矩阵、测试夹具、使用指南和发行说明，不能只改显示名称。

版本之间的高层联机流程可以复用，但原生接口、菜单结构、临时开关和发现协议仍按版本验收。未知构建保留手动启动和手动联机路径，不进入自动联机列表。
