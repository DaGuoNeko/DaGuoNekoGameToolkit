# Java 游戏实例集成方向

[返回项目首页](../README.md) · [使用指南](使用指南.md) · [架构说明](架构说明.md) · [开发指南](开发指南.md)

本文记录后续把 Java 版 Minecraft 纳入工具箱的产品方向。它描述目标能力、边界、分阶段路线和第三方组件使用原则，不代表当前版本已经支持 Java 游戏运行控制。

## 目标定义

这里的“导入 Java 存档”不是只把 `saves/<世界>` 复制进工具箱，也不是把 Java 世界转换为网易存档后就结束。目标是把一个带版本、加载器、Java 运行时、模组和世界数据的 **Java 游戏实例** 纳入工具箱管理，使它在运行时具备与当前网易存档相似的可观测、可操作和可审计能力。

Java 世界、Java 游戏实例和网易转换副本必须分开保存：

- **Java 世界**：原始 `saves/<世界>`，保留原目录和原始格式。
- **Java 游戏实例**：Minecraft 版本、加载器、Java 运行时、实例目录、模组、配置、资源包、数据包、启动参数以及其中的世界。
- **网易转换副本**：通过 Chunker 等转换工具生成的基岩副本，是独立派生物，不覆盖 Java 原地图，也不与 Java 世界自动双向同步。

最终用户体验应是：用户可以继续使用 HMCL、PCL 或其他启动器准备和启动 Java 实例，再由工具箱发现并连接这个实例；也可以在工具箱中登记实例、查看世界、预览地图、检查模组，并在支持的能力范围内控制运行中的游戏。

## 当前基础与缺口

当前项目已经具备几个可以复用的部分：

- 地图预览可以离线读取 Java 现代 Anvil 的 `region/`，不启动游戏、不写原地图。
- 地形导入已经能把 Java 来源复制到任务目录，再调用 Chunker CLI 转换为基岩来源。
- 网易侧已有会话、进程归属、代次、Host Bridge、代码执行、脚本热更新、模组目录和项目日志模型。
- 存档库已经有复制导入、原目录登记、备份、回收、恢复和路径保护。

当前缺口也很明确：

- 现有 `GamePath`、MCDK 和 Host Bridge 面向 `Minecraft.Windows.exe` 及网易版运行环境，不能直接作为 Java 启动链路。
- Chunker 目前只是架构导入的转换器，不是 Java 运行时控制器。
- 地图预览只能得到二维地表和 X/Z 范围，不能代替 Java 游戏内完整方块、实体、容器和模组状态。
- 当前没有 Java 端的受控 Bridge 模组，也没有 Java 会话适配器、加载器适配器或 Java 模组能力清单。

因此，Java 支持应作为一条新的运行时适配链路加入，而不是把 Java 进程硬塞进现有网易会话流程。

## HMCL、PCL、Chunker 与工具箱的分工

### HMCL 与 PCL

HMCL/PCL 的价值主要在于 Java 环境准备和启动器生态：Java 版本管理、Minecraft 版本、加载器、账户、实例目录、整合包和模组安装。工具箱不需要重做这些功能才能实现 Java 运行时控制。

第一阶段应优先支持“外部启动器启动，工具箱附加控制”：

1. 用户用 HMCL、PCL 或其他启动器准备并启动 Java 实例。
2. Java Bridge 模组向工具箱注册自己和当前游戏会话。
3. 工具箱按实例路径、游戏进程、世界和 Bridge 会话绑定目标。
4. 工具箱通过统一的 Java 适配器提供状态、日志、模组清单和受限操作。

后续再增加启动器适配器，让工具箱可以打开或请求外部启动器启动指定实例。启动器适配器应使用公开、可验证的入口或用户明确选择的启动命令，不依赖未承诺稳定的私有 UI 自动化、内部类或账户令牌格式。

### Chunker

Chunker 继续作为 Java → 基岩的转换工具使用。它不负责：

- 启动 Java 游戏；
- 读取 Java 游戏运行时的玩家、实体和模组状态；
- 保证 Java 模组、数据包、世界生成规则或自定义维度在网易侧等价运行；
- 建立 Java 世界与网易副本的实时同步。

转换结果必须登记为独立的网易存档或独立的转换产物，并保留来源路径、来源哈希、转换工具版本、目标格式、警告和验证结果。

## Java Bridge 目标架构

Java 运行时控制需要一个由本项目维护的 Bridge 模组。它应适配明确的 Minecraft 版本和加载器，而不是依赖 HMCL/PCL 的内部实现。

```text
DaGuoNeko
    │ 本机鉴权连接、会话代次、能力请求
    ▼
Java Bridge 模组
    │ 统一协议；加载器适配；游戏线程调度
    ▼
Fabric / NeoForge / Forge API
    │
    ▼
Java 游戏世界、集成服务端和已加载模组
```

Java Bridge 至少要处理以下职责：

- 启动握手、协议版本和能力列表；
- 游戏版本、加载器版本、实例标识和世界标识；
- 客户端、集成服务端或专用服务端的运行状态；
- 玩家、维度、坐标、区块加载和保存状态；
- 请求超时、取消、游戏重载和进程退出；
- 本机随机令牌、连接代次和目标进程绑定；
- 结构化事件和错误，不把任意游戏日志直接当成工具箱成功证据。

首版不应开放任意 Java 代码执行。当前网易侧的 Python 调试接口可以执行开发辅助代码，但 Java 端应优先采用类型化命令和能力白名单，避免把一个本机端口变成任意代码执行入口。确有开发者模式需求时，应单独加明确开关、会话确认、来源校验和审计记录。

### 单人世界与专用服务端

Java 单人世界通常包含集成服务端；方块、实体、容器和世界规则的权威操作应在服务端线程执行。客户端侧只负责界面、输入和客户端状态。专用服务端没有客户端窗口，工具箱仍应能通过服务端 Bridge 管理世界。

因此 Bridge 的协议应区分 `client`、`integrated_server` 和 `dedicated_server` 能力，不把“有窗口”当成“世界可操作”的条件。

## 运行时能力边界

首批能力应围绕可验证、可撤销和跨版本较稳定的操作建设：

| 能力 | 方向 | 约束 |
|---|---|---|
| 世界、玩家、维度、坐标和运行状态 | 首批支持 | 绑定会话代次、进程和世界标识 |
| 已加载模组列表和版本 | 首批支持 | 同时返回加载器、来源和能力版本 |
| 磁盘模组 JAR 清单 | 首批支持 | 只读扫描；不把 JAR 当成可信代码 |
| 方块、实体、容器读取 | 后续支持 | 在对应游戏线程执行，按版本能力报告 |
| 方块、实体、容器修改 | 后续支持 | 写前检查、备份或操作日志、回读和失败证据 |
| 时间、天气、游戏规则等世界参数 | 后续支持 | 区分临时运行修改与持久化配置 |
| 资源包、数据包和部分配置重载 | 按加载器支持 | 只在游戏或模组明确支持时提供 |
| 模组配置修改 | 优先做下次启动生效 | 保存前备份，检查配置格式和外部变化 |
| 安装、移除、启用和禁用模组 | 先做磁盘级管理 | 默认要求停止游戏后生效 |
| 任意模组热插拔、卸载和重新加载类 | 不作为通用承诺 | Java 类加载器、依赖和生命周期通常不允许安全卸载 |

“动态调整模组”应拆成三种行为：

1. **发现**：读取加载器实际已加载的模组和磁盘中的 JAR、版本及哈希。
2. **配置**：编辑模组提供的配置文件或已注册的运行时配置，明确是立即生效还是下次启动生效。
3. **生命周期**：安装、移除、启用、禁用和版本替换，默认停止游戏后执行，并重新生成运行快照。

只有模组自己通过 Bridge 能力注册表提供安全的运行时 API，工具箱才应提供对应的即时控制。不能把“修改 JAR 文件”描述成“运行中热更新模组”。

## Java 实例数据模型方向

后续数据模型应至少区分以下对象：

- `javaInstance`：外部启动器实例目录、游戏版本、加载器、Java 路径和启动方式；
- `javaWorld`：实例下的世界目录、世界名称、维度信息和来源身份；
- `javaMod`：模组 ID、版本、文件路径、哈希、加载器、来源和状态；
- `javaSession`：游戏 PID、实例身份、世界身份、Bridge 连接代次和能力快照；
- `javaDerivedWorld`：由 Chunker 或其他转换器产生的网易副本，记录来源和转换报告；
- `javaOperation`：读取、修改、重载、配置写入和模组变更的任务记录。

外部启动器的账户、Cookie、访问令牌和登录缓存不应复制进工具箱数据目录，也不应进入日志、任务报告或 Bridge 请求。工具箱只保存完成实例识别和运行控制所需的最小路径、版本、哈希及用户选择。

## HMCL/PCL 的许可证与内置原则

许可证状态必须以发行时的上游文件为准，以下内容是当前规划依据：

- HMCL 官方仓库标注 GPLv3，并附有修改版本改名、保留版权声明等附加条款。若整体内置或形成衍生作品，必须遵守 GPLv3、对应附加条款、许可证展示和对应源代码提供义务。
- PCL 的公开源码仓库包含自定义的“PCL 分发有限许可”，不是可以直接按 MIT、Apache 或 GPL 理解的标准宽松许可证。少量参考和大量参考、修改或重新实现实质功能的许可后果不同。
- OpenPCL 等社区分支可能声明 MIT，但这只覆盖其有权许可的代码；不能据此推断所有上游 PCL 代码、资源、二进制或品牌都自动获得 MIT 授权。
- Fabric Loader、NeoForge、Forge 及其依赖各自有许可证和版权边界；引入代码或发行二进制前必须逐项记录来源和许可。

因此默认采用以下原则：

1. 不把 HMCL 或 PCL 的完整程序、UI、内部类和私有配置解析器内置进 DaGuoNeko 发行包。
2. 只实现独立的启动器适配接口，通过用户选择的路径和公开入口联动。
3. 借鉴交互思路可以，复制实现代码、资源、文案或品牌元素必须先做来源和许可证审查。
4. 任何第三方组件进入发行包前，都要加入 `licenses/NOTICE.md`、来源地址、版本、许可证、修改说明和对应源代码义务记录。
5. 如果未来确实要发行 GPL 组件，先单独确定整个组合的许可证策略，再决定是否拆成独立下载或可选组件。

## 分阶段路线

### 阶段 0：定义支持矩阵

- 先选定一个 Minecraft Java 版本和一个加载器作为首个验收目标。
- 明确 Fabric、NeoForge、Forge 的优先级，不承诺“所有 Java 模组通用”。
- 定义 Bridge 协议版本、会话代次、能力注册表、错误码和回读证据格式。
- 建立只含公开测试模组的 Java 专用测试实例，不使用用户真实存档作为夹具。

### 阶段 1：导入 Java 游戏实例

- 选择 HMCL/PCL 或其他启动器的实例目录，或手动选择实例下的游戏目录。
- 读取版本、加载器、Java 路径、世界列表和模组清单。
- 保留原实例，工具箱只登记引用和身份信息，必要时提供受控复制。
- 将 Java 世界作为独立对象登记，并继续复用现有 Java 地图预览。
- 生成导入报告：可识别项、缺失项、未知项和需要用户确认的风险。

### 阶段 2：外部启动与运行中附加

- 用户可以继续用 HMCL/PCL 启动；工具箱通过 Bridge 自动发现目标进程。
- 按实例路径、游戏进程、世界身份和 Bridge 代次绑定会话，禁止连接到不明进程。
- 先提供只读状态、日志、玩家、世界、维度和已加载模组信息。
- 支持用户手动断开、停止或重新连接，不自动重放结果不明的副作用操作。

### 阶段 3：Java Bridge 基础控制

- 获取和修改时间、天气、游戏规则、玩家状态等低风险能力。
- 读取方块、实体、容器和区块加载状态。
- 增加写前快照、操作任务、回读验证、取消和失败恢复边界。
- 将 Java 会话接入项目日志、任务中心和现有 MCP 会话选择模型。

### 阶段 4：模组能力与配置管理

- 显示加载器实际加载结果与磁盘模组清单的差异。
- 支持模组配置文件备份、格式检查、外部变化检测和下次启动生效。
- 允许模组通过 Bridge 注册明确的运行时能力，例如刷新某一类内容或读取业务状态。
- 运行时能力按模组 ID、版本、协议版本和权限逐项授权，不按“拥有一个 JAR”自动放行。

### 阶段 5：启动器适配与转换联动

- 增加 HMCL/PCL 的可选启动适配器，优先调用公开入口或用户提供的启动命令。
- Java 实例转换为网易存档时，复用实例识别、地图预览、转换报告和备份模型。
- 转换后的网易存档、原始 Java 世界和运行时控制会话保持独立记录。
- 地图预览可以选择 X/Z 区域并创建任务，但完整三维读取和写入仍由游戏运行时确认。

## 安全与数据保护

Java 模组 JAR 可以执行任意代码，因此“用户选择了模组”不能等同于“工具箱信任该模组”。Bridge 和 Java 实例管理必须遵守以下边界：

- Bridge 使用本机随机令牌、明确会话代次和目标进程归属检查。
- 默认只开放类型化、最小权限的能力，不开放任意 Java、Groovy、JavaScript 或系统命令执行。
- 模组安装、替换、禁用和配置写入前保存清单、文件哈希和必要的世界备份。
- 不按进程名批量连接或结束 Java 游戏；必须核对实例路径、PID、父进程和启动时间。
- 不复制 HMCL/PCL 的账户数据库、Cookie、Token 或登录缓存。
- 外部实例被删除、替换、链接重定向或版本变化时停止运行控制并要求重新确认。
- 网络控制默认只绑定回环地址；远程控制必须单独设计认证、授权、审计和撤销。

## 验收标准

在宣称“支持 Java 实例”前，至少要完成以下验证：

1. 在选定的版本和加载器下导入一个公开测试实例，原实例内容哈希保持不变。
2. 通过 HMCL/PCL 启动后，工具箱能绑定正确的 Java 进程、实例、世界和 Bridge 代次。
3. 工具箱重启、游戏重载、世界切换和 Java 进程退出时不会连接到旧会话。
4. 只读状态、模组清单和世界信息能回读实际运行结果，而不是只依据启动参数推断。
5. 至少一个世界修改操作完成写前检查、执行、回读、保存和失败记录。
6. 一个模组配置修改可以明确区分“立即生效”和“下次启动生效”。
7. 模组 JAR 替换、启用、禁用和版本变化会阻止旧运行快照继续执行，或要求用户确认重启。
8. Java 原始世界、工具箱任务数据和网易转换副本可以分别备份、恢复和删除。
9. 发行包中的第三方组件、许可证、版权声明和源代码义务经过逐项核对。

## 暂不承诺

在没有对应版本、加载器和模组实测前，不承诺：

- HMCL/PCL 的所有版本都能被自动启动或自动识别；
- 任意 Fabric、Forge、NeoForge 模组都能被统一控制；
- 任意模组都支持运行时热更新、卸载或重新加载；
- Java 世界与网易副本可以实时双向同步；
- Java 模组、数据包、世界生成规则、自定义维度和实体行为可以无损转换到网易；
- 通过静态文件或地图预览就能证明游戏运行时内容已经成功加载。

这份方向文档的下一步应由具体版本矩阵和 Bridge 协议设计开始，而不是先把 HMCL 或 PCL 整体内置进工具箱。
