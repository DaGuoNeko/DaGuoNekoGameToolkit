# 开发指南

[返回项目首页](../README.md) · [架构说明](架构说明.md) · [使用指南](使用指南.md) · [共享工作规则](../AGENTS.md)

文件路径默认相对仓库根目录；所有 npm、Node 测试及下方原生构建命令在 `DesktopUI/` 执行。以当前脚本和锁文件为准，不使用旧交接中的机器路径、PID 或通过数量作为当前状态。

## 环境要求

工作区和离线数据专项：`node --test tests/world-data.test.cjs tests/workspace-context.test.cjs`；构建后 `node tests/workspaces-ui.cjs` 验证真实 preload/IPC、外部读取、比较、导出、返回与小窗口。`tests/fixtures/navigation.cjs` 定义 UI 回归使用的业务入口，页面移动时同步导航，不通过 IPC 代替界面路径。`world-data-worker.cjs` 与地图 worker 一样必须独立打包到 runtime 白名单。

性能专项：`node --test tests/resource-refresh.test.cjs tests/map-preview-cache.test.cjs tests/world-data-store.test.cjs tests/content-index.test.cjs` 检查刷新范围、快照输出等价、缓存失效和清理；构建后 `node tests/performance-ui.cjs` 通过真实 preload/IPC 确认进度通知不触发无关资源读取、实际修改仍显示。`world-data-compute-worker.cjs` 独立打入 runtime 白名单；发行验收可设置 `DGN_GAME_TEST_EXE` 执行 performance-ui 和 workspaces-ui。

| 用途 | 要求 |
|---|---|
| 普通界面和主进程开发、出包 | Windows x64、Node.js 22.12+、npm、Windows PowerShell、.NET Framework C# 编译器 |
| 安装依赖 | `DesktopUI/package.json` 与 `package-lock.json`，使用 `npm.cmd ci` |
| 重编自有 C/C++/汇编桥及原生测试探针 | Zig 0.13.0；普通 JS 开发可使用仓库已有运行库 |
| 游戏实测 | 自行安装对应网易开发版游戏，使用专用测试地图和模组 |
| 官方 UI 引擎预览 | MCStudio 配套 `Minecraft.Windows.Editor.exe` 及资源 |
| 官方 Tracy 窗口 | 自行准备兼容的 `tracy-profiler.exe`，当前协议为 0.11.1 |
| 远程联机实测 | 固定版本 EasyTier 组件由应用首次使用时获取；房主另备樱花 TCP 隧道 |

网络助手使用 `%WINDIR%/Microsoft.NET/Framework64/v4.0.30319/csc.exe`。构建会检查已缓存网络组件的哈希；没有缓存时按 `native/network-helper/runtime-files.json` 生成助手和清单，不要求预先下载 EasyTier。

普通构建无需桌面 Python，也不需要 Python `.venv`。游戏内 Python 2.7 与独立的 Python MCP 工具是不同运行时。Node、Zig 可以另行使用便携目录，但仓库当前未提供自动下载或自动切换工具链的入口，不应把目录规划视为已实现功能。

表中的临时子目录是使用约定，按任务需要创建，不必先生成空目录。详细归属、manifest、三天 TTL 和清理边界见[开发产物生命周期](开发产物生命周期.md)。正式测试不应长期藏在任务目录；临时脚本成熟后再将所需部分纳入 `tests/` 或 `scripts/`，并补充验证。

`.gitignore` 对未跟踪文件起作用，已经被 Git 跟踪的文件不会因新规则自动退出版本控制。被忽略不代表已备份、已同步或可以公开；换设备时这些目录不会随 clone 恢复。源码仓库不保存机器交接资料，现有针对旧交接文件名的忽略规则用于防止误加入。

`.env`、`.env.example`、`.env.local`、`.mcdev.json`、共享 `.vscode/` 和项目本地环境文件默认保留在 Git 可见范围内，便于其他设备恢复开发环境；真实密钥只能由明确的 `.env.private`、`.env.*.private` 或 `.secret` 文件承载。系统垃圾文件直接删除，不用 `.gitignore` 隐藏。新增文件后检查 `git status --short`，必要时用 `git check-ignore -v -- <路径>` 核对规则。

## 安装与构建

从仓库根目录进入应用目录：

```powershell
Set-Location DesktopUI
npm.cmd ci
npm.cmd run build
```

`npm ci` 按锁文件安装，并会重建已有 node_modules；只在首次准备或依赖变更等需要时执行。不要为解决环境问题随意升级所有依赖或借用另一个产品的 node_modules。

`build` 会编译网络助手与窗口观察/截图助手，使用 esbuild 生成界面、主进程、两个 worker 和 MCP stdio 构建，并复制 preload、HTML、图标及自动化脚本。`scripts/build-capture.ps1` 使用系统 .NET Framework 编译器及 Windows WinRT 元数据，将 `electron/automation-window.cs`、`electron/automation-capture.cs` 编译到被忽略的 `runtime/automation/automation-window.dll`；不需要额外下载 Windows SDK。其他原生 DLL/WASM 不会全部重编。应用实际入口为 `dist/main.cjs`。

构建保留 `mainFields: ["module", "main"]`，避免 jsonc-parser 选到 UMD 后留下缺失的相对 require。WASM 构建会去除调试路径元数据，保留执行节；运行库、worker 和普通 Node 的外置入口应按打包白名单核对。

## 开发启动与测试隔离

`npm.cmd start` 先构建再运行 Electron；当前没有配置工具箱源码的 watch/HMR。修改应用源码后重新构建、重开，不能把游戏模组热更新当成 Electron 源码热更新。

不设置环境覆盖时，源码应用使用日常 `%LocalAppData%/DaGuoNeko_GameToolkit/` 数据，并登记 MCP 启动入口。开发前明确是否允许使用该数据，避免无意将日常 MCP 指向开发构建。

| 变量 | 作用与限制 |
|---|---|
| `DGN_GAME_DATA_DIR` | 指向专用测试数据目录，改变配置、日志、MCP 和测试存档位置；同时影响部分外部进程冲突检查，不能作为真实游戏完全隔离的保证 |
| `DGN_GAME_HEADLESS=1` | 自动化隐藏窗口并跳过部分关闭确认，仅用于测试 |
| `DGN_GAME_TEST_EXE` | 支持该变量的 UI 测试使用指定的实际发行 EXE |
| `DGN_UI_BUNDLE_DIR` | multi-hosts/rooms 等夹具测试读取指定构建资源，先查对应测试的参数 |
| `DGN_TEST_RELOAD_SOURCES=1` | multi-hosts UI 测试开启来源变化与重启专项 |

优先使用现有 UI 测试创建的独立临时数据和测试启动器。手动 UI 调试可以选用专用目录，但不得导入真实存档并据此宣称已经隔离。独立主机仍使用其专用用户目录，官方编辑器引擎也有真实 Roaming 下的世界目录；环境变量不能替代路径和进程归属校验。

测试结束恢复修改前的环境变量值。真实游戏验证使用明确的测试存档、已核对的 EXE、自己的会话及源码来源，不覆盖日常游戏设置或结束未知进程。

## 测试与验收

先跑与改动直接相关的检查，再完成必要回归；以下命令不是每次必须全部执行的串行脚本。

| 层 | 入口 | 验证范围 |
|---|---|---|
| 服务逻辑 | `npm.cmd test`；或 `node --test tests/<目标>.test.cjs` | 配置、状态机、进程边界、日志、存档、协议和失败路径 |
| 串行服务回归 | `node --test --test-concurrency=1 tests/*.test.cjs` | 高负载时区分并发环境问题；记录失败及复测，不放宽产品保护 |
| 常规 UI | `npm.cmd run test:ui` | 当前 UI 测试集合使用测试启动器和临时数据 |
| 调试 UI | `npm.cmd run test:debug-ui` | 模拟游戏与真实鉴权通信下的调试流程 |
| 多主机与房间 UI | `node tests/multi-hosts-ui.cjs`、`node tests/rooms-ui.cjs` | 专项夹具；不使用 DGN_GAME_TEST_EXE 选择真实发行 EXE |
| 版本选择与本机加入 UI | `node tests/game-versions-ui.cjs`、`node tests/local-join-ui.cjs` | 实际 IPC 与界面下的版本能力、目标选择及失败状态夹具，不等于真实游戏入房 |
| MCDK 运行链 | `node tests/worlds-runtime.cjs` | 实际 MCDK、隔离数据和测试游戏 EXE，不是真实 Minecraft |
| 最终发行 EXE | `node tests/distribution-ui.cjs`、`node tests/rooms-package-ui.cjs` | 先设置 DGN_GAME_TEST_EXE；首次启动、持久化及发行入口 |
| 真实游戏 | 按任务使用独立测试地图和目标会话 | 真正加载、持久化恢复、多人、资源和热更新行为 |

本机多组真实验收可显式设置 `DGN_LIVE_GAME_EXE` 后运行 `node tests/local-multiplayer-live.cjs`；指定 `DGN_GAME_TEST_EXE` 时改用最终发行 EXE。脚本新建两张地图、同 UUID/模块名的两份不同源码和四份私有运行目录，验证 UI/MCP 分别入房、房主玩家名单、A 组脚本热更与停止 A 后 B 仍可用；只保存并关闭该测试实例创建的会话，不使用真实业务地图或远程隧道。数据和输出统一写入 `.miao/work/<任务ID>/data/` 与 `.miao/work/<任务ID>/outputs/`，任务默认保留三天。

默认服务测试并发度为 4。`tests/worlds-ui.cjs` 是 profiles UI 的兼容入口。原生隔离探针未构建时，对应测试会跳过，不能把跳过计作原生验证通过。模拟游戏、ASAR UI、发行 EXE 和真实游戏应分别报告；历史通过数量不是当前验收结果。

AI 控制专项见 [AI 自动化接口](AI自动化.md)：`tests/automation-control.test.cjs` 含真实 Windows 隐藏断言夹具，`tests/automation-ui.cjs` 验证 UI/IPC 与 MCP 互通，`tests/automation-live.cjs` 要求显式 `DGN_LIVE_GAME_EXE`，新建两份独立测试地图检查定向截图、固定拍摄和停止后另一主机仍可用。开发用 `scripts/toolbox-call.cjs --jsonl` 可复用同一 MCP 连接；该脚本不随发行包分发。

Python 脚本验收统一通过 `tests/fixtures/python3.cjs`：显式 `DGN_TEST_PYTHON3` 优先；未设置时 Windows 尝试 `py -3`，再尝试 `python3` / `python`，先检查主版本必须为 3。缺少 Python 3 会明确失败，不把缺失探针算通过；测试源码补充 UTF-8 声明，不向 JSON 标准输入插入声明。不会改变系统 PATH 或游戏自身的 Python 2.7。

地图预览使用 `node --test tests/map-preview.test.cjs` 验证 Java/基岩已知地标、轴序、高度、调色板、PNG 瓦片像素、坡面/水深、内置颜色和 ZIP 校验及来源不变。测试还将预览服务单独打成 bundle，在只允许读取测试目录、禁止外部图片/JAR 和联网的子进程中验证两类地图。构建后运行 `node tests/map-preview-ui.cjs` 通过隐藏 Electron 窗口验证真实 preload/IPC 与像素交互，并禁止外部 JAR 读取。可用 `DGN_MAP_JAVA_ZIP` 指定额外的 Java ZIP 作只读验收，测试前后比较其哈希。界面测试只替换原生文件对话框的选择结果，不替换渲染结果；截图和结构化结果写入当前 `.miao/work/<任务ID>/outputs/`。这不等同于最终发行 EXE 或游戏内验证。

`electron/domains/worlds/map-palette.json` 是随 Git 维护的内置方块 RGB 数据，记录 Java 1.21.1 顶面颜色统计，不含纹理图、模型、机器路径或玩家数据。普通 build 由 esbuild 直接嵌入此 JSON，不运行外部素材扫描或下载；更新颜色时修改数据表并运行地图专项验证。

地图任务由 `map-preview-jobs.cjs` 管理单个后台线程、请求 ID、进度、取消、批次回传和临时目录。`build` 将线程入口及依赖打入 `runtime/automation/map-preview-worker.cjs`，出包白名单包含它；普通 Node Worker 不读取 ASAR 内脚本。每次任务限时 120 秒，V8 老生代预算 768 MiB、年轻代 64 MiB（不等于整个进程 RSS 上限）；单次请求只读取当前视野尚未加载的区块，图片缓存限制约 256 MiB，基岩最多扫描 500 万条记录。Java 和基岩都按视野区块过滤；取消后等待线程结束再清理其专属目录。

`node --test tests/map-preview-jobs.test.cjs tests/file-selection.test.cjs tests/python3.test.cjs` 验证后台线程、取消/超时、远处区域、选择身份和解释器；`node tests/file-selection-ui.cjs` 经真实 IPC 验证路径替换与重新选择。发行工作流分别在构建后与出包后运行地图 UI 验收；地图测试显式恢复主世界，不依赖可选的外部 ZIP 参数切换维度。

真实本机多人测试先核对 toolbox_status/list_worlds/list_clients，再 launch_world 并等待 game_ready；客机用 launch_joined_client 指定 hostSessionId、不同玩家名和独立 requestId，同一次请求重试复用原 ID。只有 autoJoin.phase=joined 才算实际入房。后续代码/重载操作核对 sessionId/generation；日志按工具实际 schema 调用，桌面键鼠串行。

版本相关回归：`node --test tests/engine-profile.test.cjs tests/global-game.test.cjs tests/client-join.test.cjs tests/local-client-isolation.test.cjs`，界面回归用 `node tests/game-versions-ui.cjs` 和 `node tests/local-join-ui.cjs`。前者覆盖程序指纹、启动竞态和构建拒绝；UI 覆盖能力表、未验证程序筛选、手动选择保存、房主版本锁定及停止后的失败提示。夹具不能替代实机证据。

真实单机双开脚本为 `node tests/local-multiplayer-live.cjs`，运行前把 `DGN_MULTIPLAYER_GAME_EXE` 指向待测游戏 EXE。它使用新建测试存档，经 MCP 启动房主/来宾，检查 `joined`、服务端玩家回执、指纹相同、目录隔离及定向停止；另外在房主运行后修改测试实例的全局程序，验证来宾仍跟随房主快照。只允许登记了完整隔离能力的构建；数据和输出统一写入 `.miao/work/<任务ID>/data/` 与 `.miao/work/<任务ID>/outputs/`，任务默认保留三天。缺少某构建时保留待验证状态，不以另一构建通过代替。

新增支持版本时，先核对 `electron/supported-engines.json` 的实际 SHA-256，再逐项验证原生桥、OreUI 菜单、玩家名、UDP 发现、入房回执和目录隔离。仅将通过的能力标为 true；自动入房与完整隔离是不同能力。网络助手由 build 从同一表生成名单，不能只改下拉框、目录名或静态说明。

## Git 提交与版本

每次提交、amend 或合并提交都先检查 `git status --short --branch`，读取近期提交的完整标题和正文（如 `git log -5 --format=full`），再核对本次差异；合并时还要逐一读取指定原提交的正文和差异。历史格式、变更内容和用户已确认的版本共同决定最终提交说明，不能只参考最近的一行标题。

标题默认沿用 `release: <当前版本>`，同一版本内补充或合并保留该版本标题。正文使用中文，按历史的“更新”“修复”（有修复时）和“验证与范围”组织，与 `docs/releases/<当前版本>.md` 保持内容一致；写清用户可见行为、必要的实现边界、实际验证及限制。模板如下，提交前替换占位内容：

```text
release: <当前版本>
```

合并提交是在原有信息基础上整理、去重、修正和补充：保留所有仍有效的变更说明，补齐新纳入的改动，明确已被后续修复替代的结论。不能只恢复某一条旧正文而遗漏其他提交，也不能只留下标题或“合并提交”。验证信息须对应最终内容：不原样沿用过时测试数量、失败状态或旧包哈希；未复测的历史证据应注明范围。用户要求合为一个提交时，版本文件、说明和功能改动一起收束，不另拆一个版本提交。

提交说明先用 UTF-8 文件保存完整标题与正文（临时文件按任务产物规则放置），再用 `git commit --file <说明文件>`；amend 使用 `git commit --amend --file <说明文件>`。禁止用只有标题的 `git commit -m` 覆盖详细说明，也不能在变更范围扩大后直接 `--no-edit` 或复用旧消息而不检查内容。提交后执行 `git log -1 --format=%B`、`git show --stat HEAD` 和 `git status --short --branch`，核对标题、正文、文件、父提交和约定提交数量；纯合并还应比较合并前后的文件树，确保内容未丢失。

项目版本必须跟随 Git 版本记录和用户已确认的版本计划，默认不增加。先对照提交正文、标签及其指向、`package.json`、`package-lock.json`、README 和 Release Notes；存在分歧时说明证据并询问用户，不根据最大的版本数字、旧标签存在或一次出包自行推算下一版。每次升版前必须说明当前版本、目标版本和理由，取得用户明确同意后才修改；本次已明确同意该目标版本的无需重复询问。“提交”“收口”“合并提交”及含糊的“提一个版本”均不构成升版确认。

经确认升版时，同步 package/lockfile、README、Release Notes 和提交标题；未确认时保持当前版本。提交、升版、打标签、推送与正式发布分别按用户授权执行，合并不自动移动或覆盖已有标签。`release:` 提交标题与本地包都不等于已发布版本；正式发布仍须匹配标签和完整发布资产。

## 出包与分发

```powershell
npm.cmd run package
```

此命令先清理旧的本地发行物，再构建并生成 `release/DaGuoNeko-Game-Toolkit-win32-x64/`、带 package.json 版本号的 ZIP 和 `.sha256`。如果标准发行目录正在运行，改在 `release/build-时间戳/` 生成；该目录仅在进程占用期间保留，后续出包会清理。

每个开发窗口结束自己的任务前，必须先完成必要验证并运行 `npm.cmd run package`，生成当前版本的最新本地 Release，作为本窗口的收口证据。本地出包不等于 GitHub Release；`release-info.json` 中 `sourceDirty: true` 的包只能作为本机测试包，不能交给 `release:publish`。

版本按[Git 提交与版本](#git-提交与版本)核对，默认不升版；每次提升都须先取得用户对目标版本的明确同意。并行窗口的功能改动可以合并，但版本推进和 Release Notes 由用户指定的窗口统一维护，不能因本地出包自行递增。

`release/` 默认只保留当前工作版本的标准目录、ZIP 和 `.sha256`。旧的未发布 ZIP、旧解压目录和未运行的 `build-*` 目录由 `npm.cmd run package` 开始时自动删除；当前进程占用的发行目录暂时保留。需要单独清理时先运行 `npm.cmd run clean:release` 预览，再运行 `npm.cmd run clean:release:apply`。

正式发布必须在功能验证完成后单独确认版本、Release Notes、干净提交、标签、GitHub Actions 资产、ZIP 和 `.sha256`；没有这组完整资产就不能称为已发布版本。

包中包含 app.asar、指定 runtime、licenses、`distribution/使用说明.txt`、`release-info.json` 和逐文件 `SHA256SUMS.txt`。EasyTier 等首次下载的网络组件不进入分发 ZIP。源码、研究资料、测试输出和个人数据不随包分发。

### 公开 GitHub Release 更新

版本更新使用当前公开仓库的 GitHub Release。每个版本必须上传以下三个资产，名称必须与 `package.mjs` 生成的版本一致：

```text
DaGuoNeko-Game-Toolkit-<version>-win-x64.zip
DaGuoNeko-Game-Toolkit-<version>-win-x64.zip.sha256
latest.json
```

客户端通过 `electron/domains/update/update-config.cjs` 中的公开更新清单地址匿名检查，不保存 GitHub 身份，也不需要用户授权。清单记录版本、固定下载地址、ZIP SHA-256 和更新说明；下载时仍再次校验 SHA-256。

日常迭代发布（拥有仓库写权限的成员，且用户已明确同意目标版本及提交、打标签、推送和发布；下方 `<已确认版本>` 须替换为该版本，命令不是默认授权）：

```powershell
npm.cmd version <已确认版本> --no-git-tag-version
# 更新 README 和该版本 Release Notes，完成验证；按上节准备完整提交说明。
# 功能和其他文档仅暂存本次明确约定的路径；以下列出版本文件。
git add package.json package-lock.json ../README.md ../docs/releases/<已确认版本>.md
git commit --file <UTF-8提交说明文件>
git log -1 --format=%B
git tag v<已确认版本>
git push origin main
git push origin v<已确认版本>
```

`.github/workflows/release.yml` 在版本标签推送时运行 Windows 构建、服务测试、更新 UI 和发行 EXE 检查，再生成完整 ZIP、校验文件和 `latest.json`。工作流使用 GitHub 自动提供的 `GITHUB_TOKEN`，只在发布任务授予 `contents: write`。工作流失败不会发布半成品；可从 Actions 的 Run workflow 输入同一标签重试。已发布的正式版本禁止覆盖，后续修复须先取得用户对新版本的明确同意再发布。

本地紧急发布仍可使用 `npm.cmd run package`、`npm.cmd run release:publish -- <产物所在目录>`，维护者需要使用 `gh auth login` 登录发布权限；这个身份只用于发布端，不会进入客户端。发布脚本检查干净工作区、标签提交、ZIP 中的版本与构建提交、SHA-256 和版本说明；仅上传到草稿，三个资产都成功后才正式发布。

若 Windows 上浏览器可访问 GitHub，而 Git 连接持续失败，先核对网络和当前 Git 支持的 TLS 后端。只有支持 OpenSSL 的 Git 构建才可尝试 `git config --local http.sslBackend openssl`；出现 Unsupported SSL backend 时用 `git config --local --unset http.sslBackend` 恢复默认。这是单仓库设置，不修改其他仓库，也不关闭证书校验；网络代理或组织权限问题仍需按实际错误处理，不能用 `sslVerify=false` 绕过。

`docs/releases/<version>.md` 是该版本发布说明来源，工作流将它写入 GitHub Release body。客户端读取公开更新清单和分页历史列表（每页 30 条），不显示草稿；历史中的预发布标记展示，但不作为自动安装目标。缺少 ZIP 或校验文件的 Release 仍可展示说明，下载按钮不可用。公开清单缺失时会回退读取最新 Release；请求使用 Electron 网络栈沿用系统代理。

其他用户在新设备解压发行 ZIP 后无需 GitHub 账号即可检查和下载公开 Release；源码运行时仍使用 Git 更新，发行包更新不会覆盖用户数据目录。

安装前先停止本工具游戏、房间并保存草稿。独立 PowerShell 脚本从缓存目录运行，重新校验 ZIP 的 SHA-256、路径、版本和 EXE/ASAR 结构；在程序同一磁盘暂存，等待旧进程退出后切换目录。每次保留唯一的 `.previous-<随机值>` 备份，不删除已有备份；切换或操作系统启动调用失败时尝试恢复，不把启动后业务崩溃宣称为自动回滚。结果保存在用户数据的 `update/update-result.json`，失败原因会在下次启动的更新页展示；旧备份需用户在确认新版本正常后自行清理。用户数据目录不参与替换。

更新专项验收：`node --test tests/update.test.cjs tests/update-install.test.cjs tests/update-launcher.test.cjs` 验证网络状态、历史分页、凭据隔离、完整性、实际 Windows 文件替换及更新进程在客户端退出后继续执行；`node tests/update-network.cjs` 用实际 Electron 网络栈验证手动重定向、流式响应与取消；`node tests/update-ui.cjs` 使用真实构建界面、preload、IPC 和服务，仅模拟 GitHub 网络边界，保存启动/定时弹窗及浅/深色历史界面截图。网络夹具不等于真实 GitHub 发布验收。

指定 `DGN_GAME_TEST_EXE` 后可显式运行 `node tests/update-live-ui.cjs`，验证真实公开 Release 和界面。测试使用独立临时数据目录，不读取浏览器登录信息或用户令牌，结束后清理测试目录；另需验证真实更新包下载及升级结果，不能只以版本接口成功代替完整安装验收。

GitHub Windows runner 的默认 TEMP 可能含 `RUNNER~1` 短路径。工作流使用 `fs.realpathSync(RUNNER_TEMP)` 设置本次任务 TEMP/TMP，避免短路径触发项目的目录重定向保护；不通过放宽产品路径校验来让测试通过。

Windows 安装进程由 `native/update-launcher/Program.cs` 编译的无窗口启动器托管。构建自动生成 `runtime/native/update-launcher.exe`，无额外管理员授权。启动器和脚本复制到更新缓存后运行，主程序收到含进程身份和版本的准备回执才退出；否则保留窗口和专属日志。不能直接把 PowerShell 标记 detached，也不能让安装程序随客户端退出。准备完成后再次检查游戏/房间/草稿，条件变化会写取消标记，在替换前终止。

完整升级验收应以正常进程方式启动隔离的低版本客户端，再连接其界面；核对安装目录版本、自动重启、窗口可见、授权和用户数据保留。部分测试启动器会在目标退出时收回子进程，不能把这种运行方式当成安装重启成功的证明。只对后台启动器隐藏窗口，重新启动的客户端使用正常窗口样式。0.1.0–0.1.2 用户需先解压运行 0.1.4 完整包一次；0.1.3 升级后窗口未显示时可重新打开软件恢复。

出包后对本次实际 EXE 验证，而不是默认测试旧目录。支持的测试变量可按下例临时设置（路径替换为本次产物）：

```powershell
$previousTestExe = $env:DGN_GAME_TEST_EXE
try {
    $env:DGN_GAME_TEST_EXE = (Resolve-Path 'release/DaGuoNeko-Game-Toolkit-win32-x64/DaGuoNeko-Game-Toolkit.exe').Path
    node tests/distribution-ui.cjs
    if ($LASTEXITCODE -ne 0) { throw '发行入口验证失败' }
    node tests/rooms-package-ui.cjs
    if ($LASTEXITCODE -ne 0) { throw '发行房间界面验证失败' }
} finally {
    if ($null -eq $previousTestExe) {
        Remove-Item Env:DGN_GAME_TEST_EXE -ErrorAction SilentlyContinue
    } else {
        $env:DGN_GAME_TEST_EXE = $previousTestExe
    }
}
```

Electron 缓存缺失时允许打包器正常下载；网络失败不等于源码错误。ASAR、dist、外置运行文件、许可证与 ZIP 应对应同一次构建。普通 Node/helper 的脚本不能依赖 Electron 的 ASAR 读取能力。

不要覆盖正在运行的发行目录。分发完整 ZIP，不单独分发 EXE。软件与源码目录不同，构建不会自动更新其他桌面副本；新版启动还可能更新本机 MCP 登记，切换前先保存自己的游戏进度。
