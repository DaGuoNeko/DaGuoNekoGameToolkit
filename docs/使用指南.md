# 使用指南

[返回项目首页](../README.md) · [开发指南](开发指南.md) · [架构说明](架构说明.md)

本页保留工具箱的详细操作方式和功能边界。UI 文件编辑与官方引擎预览分别见 [UI 编辑器功能对照](UI_EDITOR_STATUS.md) 和[官方编辑器引擎预览](EDITOR_ENGINE.md)。文中的历史实测范围不代表当前设备已完成验证。

## 使用方式

### 工具箱版本更新

在“设置 → 工具箱更新”中先完成 GitHub 授权。此功能只面向拥有项目私有仓库读取权限的成员；授权会在浏览器中完成，工具箱只在当前 Windows 用户的安全存储中保存用户令牌，不保存维护者 Token。

早期 0.1.0–0.1.2 更新启动器存在退出后未安装的缺陷，需先将 0.1.3 或更高版本的完整 ZIP 解压到新目录并打开一次；现有配置、存档与 GitHub 授权沿用。后续版本使用内置更新即可。

首次授权后，工具箱会在启动时和运行期间每 6 小时自动检查正式版本；发现新版会弹出提示，同一次运行不会重复弹出同一版本。也可以随时在设置页点击“检查更新”。授权会跨重启和升级复用，无需每次更新重新登录；主动退出、授权失效或被撤销时才需重新授权。

“更新历史”显示 GitHub 版本号、发布时间和发布说明，可展开各版本并“加载更早版本”。预发布版本会单独标记，不自动安装；草稿不展示。发现新版后点击“下载更新”，工具箱下载对应 ZIP 并校验 SHA-256；下载完成后点击“重启并安装更新”，由独立脚本替换程序目录并重新启动。用户配置、日志、存档和模组目录不在程序目录中，不会被更新覆盖。源码运行时使用 Git 更新，避免把开发目录替换为发行包。

安装更新前必须先停止游戏会话和联机房间。更新包不完整、校验失败、当前程序正在运行或发布缺少校验文件时，更新会停止并保留当前版本。

点击“重启并安装更新”后先显示“正在校验并准备安装”；安装程序确认准备就绪后才退出当前客户端。准备失败会保留窗口并提示原因。请勿在准备期间启动游戏或修改配置。

“仓库已连接，尚未发布正式版本”表示授权可用但还没有正式发布；“无法读取此私有仓库（HTTP 404）”需要确认登录账号、仓库邀请或组织授权。更新日志中的内容按文本显示，不执行 HTML 或脚本。安装保留程序旁的 `.previous-…` 旧版本备份，失败时尝试恢复，并在下次启动显示安装结果；确认新版本正常后可自行清理旧备份。

### EasyTier＋樱花联机房间（实验验证阶段）

侧栏“联机房间”提供固定邀请码、创建、复制邀请与加入。房主先在樱花创建 TCP 隧道，本地 IP 为 `127.0.0.1`，本地端口默认 `11010`；将隧道显示的公网 `地址:端口` 和相同本地端口填入工具箱。房主设置自定义邀请码、选择存档后创建房间，将 DGNROOM2: 开头的完整固定邀请发给朋友。不设产品有效期，同一邀请码和本机房间数据可跨关闭分享、工具箱重开复用；更换邀请码后重新创建会使旧邀请失效。完整邀请含樱花地址与房间身份，不能只把自定义短码发给首次加入的朋友；公网地址/端口改变后需重新复制一次。邀请、玩家名、自定义邀请码和创建参数会自动保存，加入后不清空；可主动清除已保存的加入信息。房间身份及加入信息使用 Windows 当前用户加密保存。朋友在全局设置中指定自己的游戏程序后，只填写完整邀请与不同玩家名即可加入；两端需使用同一开发版构建，已支持 `3.10.0.420447` 和 `3.10.0.436581`；房主和来宾均需新版工具箱。来宾使用游戏原生资源包协商下载，不再要求预先持有相同模组。网络与游戏入房分别显示状态，只有房主收到玩家回执才标记成功。

首次联机从固定的 EasyTier 官方发行包下载并校验组件（`2.7.0-8b7f1f01`，上游预发布版）；网络助手需要 Windows 管理员授权，主界面保持普通权限。组件缓存位于工具箱数据目录 `network-components/`。发行 ZIP 不直接分发 Npcap Packet.dll；首次下载的原始运行组件必须完整保留，不能单独删掉 DLL。开发构建无需预先下载网络组件；构建脚本根据固定哈希生成网络助手和清单，详见[开发指南](开发指南.md)。

当前固定走樱花 TCP 入口，不启用自动 P2P 打洞。每份邀请有独立临时凭据；撤销后不能继续使用。关闭分享保留房主游戏，朋友主动离开只停止此次加入的客户端；清理只作用于本次网络进程及防火墙规则，不管理其他 EasyTier 实例。邀请码包含访问凭据，请仅交给参与测试的朋友。

双方使用支持自动重连的新版工具箱、工具箱保持运行且原邀请仍有效时，房主重载世界或退出并重新启动同一存档，会保留虚拟网络和原邀请。朋友的游戏进程保持打开，页面显示“等待房主恢复”；房主恢复后自动重新定位房间、验证入房，并重新建立 Python 脚本同步，无需再发送邀请。恢复时核对当前引擎实际存档路径和游戏版本，不跟随房主进入其他地图。每次恢复使用新的房间代次与随机入房证明；已使用邀请绑定原来宾实例的重连凭据，其他客户端不能接管。固定邀请没有产品到期时间，关闭分享后用相同邀请码重新创建仍可使用；朋友主动离开或退出工具箱后可用已保存信息再次加入。旧 DGNROOM1 临时邀请继续按原来的到期/撤销规则处理。更换邀请码、清除工具箱本机房间数据或改变樱花入口，需要重新分享完整邀请。

重连只对本工具所属客户端临时开放原有回环菜单端口，完成或超时后再次封闭，旧连接不会因新一轮重连重新获得访问。遇到断言、菜单未就绪或结果不明时保留客户端并显示“重连需要处理”，可检查后点“重试重连”；同一不确定入房操作不会无限重放。不同 Windows 用户的测试端按已验证 SID 区分，另一用户的游戏不占用本账户的原生存档目录；无法确定归属时仍保留保守检查。

本机两个工具箱实例也可以通过邀请测试：只有邀请中的房主地址确实属于本机、且房间鉴权通过时，来宾才复用房主网络，避免重复创建冲突网卡；界面显示“本机共享房主网络”。其他网段冲突仍会拒绝。自动重连保留原来宾实例；朋友主动离开后以新客户端同名加入，仍应撤销旧邀请并生成新邀请。

邀请加入只需要邀请文本与玩家名，不读取或创建已登记的启动配置。使用全局游戏程序、默认启动参数和全局游戏设置，为本次客户端生成临时运行快照；不加载本地业务模组和自动热更新，保留内置调试辅助模组用于房主身份回执。全局游戏程序缺失、无效或版本不匹配时在启动网络前提示；原配置保持不变。双方不再计算或比较模组内容哈希，由游戏原生协商世界所需的包。如游戏提示资源包，请选择“下载并加入”；工具箱的“已进入游戏”表示玩家进入并经房主确认，不是逐项资源加载证明；是否强制下载由游戏的世界资源包设置决定。当前入房等待仍为约 120 秒，大体积包可能超过期限。地图由房主持有并保存，工具箱不合并双方存档。已通过独立 Windows 标准用户、空原生缓存及房主目录拒绝访问测试：customNPC 与 DAGUOMIAO_API_MOD 的 4 个包、2,463 个文件（47,903,654 字节）由游戏原生下载，逐文件哈希一致；实际脚本、贴图、传送石模型和全局设置 UI 正常，并完成来宾保存→房主回读→重新打开→恢复原值。专用测试包另完成两次冷缓存加入。此结论覆盖上述模组，不承诺任意模组、目录外依赖或全部业务功能均兼容。

双方使用支持联机热更新的新版工具箱后，入房即开启 Python 脚本同步。房主启动配置需开启“自动热更新 Python 模组”，保存已有脚本的函数/方法修改后，朋友端自动接收并热更新，无需退房重进；房间页显示本机状态和每个朋友的回执。同步使用现有邀请鉴权及加密房间通道，只发送本次启用且允许热更新的行为包 Python 文件；来宾只更新当前游戏实际加载的原生下载包，逐文件 SHA-256 和语法校验通过后才写入并更新已加载模块，不改来宾的启动配置或独立模组工程。关闭房间/撤销邀请后停止同步。旧版房主或来宾可继续普通联机，但不提供此同步能力。

联机热更新保留游戏原生 Python 更新边界：不自动重跑初始化，也不把 UI JSON、贴图、模型、包清单当成 Python 代码更新。新增/删除脚本文件或变更包版本需重新创建房间并加入；单文件最多 2 MiB、房间 Python 总量最多 64 MiB、单次最多 256 个变化文件。传输损坏、语法错误、来宾文件被其他操作修改或更新未获确认时显示失败，保持房间连接，不反复执行同一失败批次；修正房主代码形成新版本后可继续同步。该功能是房主到来宾的单向更新，不合并双方修改。

验证边界：同机两个真实 Minecraft 客户端已完成创建、邀请、OreUI 入房和房主回执验证；双方互相可见，玩家 ID 不同，服务端移动来宾后客户端坐标同步，恢复原位后同名来宾退出再加入通过。联机脚本同步另使用独立 Windows 用户、空原生下载缓存和房主源码拒绝访问验证，覆盖连续代码变更、75 KB 分片、语法错误保留旧代码与修正恢复，两个游戏进程及玩家身份保持不变。另有同机两 EasyTier 实例经樱花公网入口的凭据认证、数据往返及撤销证据。这些不能合并表述为异地游戏实测；两台独立网络电脑上的持续游戏与热更新仍需验证。

1. 完整解压，运行 `DaGuoNeko-Game-Toolkit.exe`。
2. 先到“设置 → 全局游戏程序”选择游戏 EXE，新建启动配置默认共用它。“启动配置”以卡片展示各套配置的玩家、游戏程序、模组数量和运行状态，支持按名称搜索。点击“编辑配置”设置玩家、模组与热更新选项；需要单独版本时取消“使用全局游戏程序”并选择 EXE。卡片上可直接复制、重命名、删除配置或“启动客户端”（不自动进入存档）。返回卡片保留未保存草稿，切换编辑其他配置时会确认是否放弃草稿。
3. 首页直接显示存档卡片。新建或编辑存档时选择“使用启动配置”，并在存档里设置游戏模式、种子、作弊、死亡不掉落、天气、昼夜和实验性选项。
4. 点击卡片“启动此存档”进入存档控制台：上方显示存档与会话信息，下方提供即时指令、给予物品、天气/时间/模式快捷操作和自定义功能卡片。需要不加载业务模组的额外客户端时，返回存档列表，点击“启动空白客户端”，输入玩家名字或随机英文名后启动，在游戏内手动加入联机。需要加载配置中的模组时，仍可从启动配置卡片点击“启动客户端”。
5. “运行日志”上方常驻会话卡片，显示配置、玩家、存档/客户端、PID 和运行状态，点击即可切换独立日志。右侧设置可收起，用于筛选、历史、导出和停止所选会话。退出整个工具箱会结束本次实例启动的所有会话，需要确认。

不再需要“当前项目”或项目目录。模组仅从配置里启用的目录加载，目录支持拖入、单独启用与热更新。内置官方 MCDK v1.6.1，游戏本体由本机开发环境提供。

侧栏“模组库”集中管理模组名称和目录，保存在 `%LocalAppData%/DaGuoNeko_GameToolkit/mods.json`。首次打开会从已有启动配置中按路径去重收录，以后可手动“从启动配置收录”，支持添加、编辑、移出和目录拖入。移出模组时会同步清理所有启动配置中同路径的条目，包括停用项和重复项，保留其他配置字段、注释和磁盘模组文件；当前可解析的配置草稿也会同步清理，并保留其他未保存修改。已运行游戏继续使用本次启动快照，下次启动生效。更改库中的路径仍不自动替换配置中的旧路径。配置和模组库保存均有备份及版本冲突检查；配置损坏时先停止清理，中途写入失败会报告已清理范围并保留库记录供修复后重试，不覆盖外部修改。

每张模组库卡片可“打开文件夹”；配置编辑器的模组条目也提供文件夹图标，包括只保存在该配置中的目录。打开前会核对已登记路径和目录状态，不通过任意文件路径执行程序。

编辑启动配置时，模组列表优先显示，可以搜索名称/路径，快速勾选启用或取消启用，单独设置热更新，也可批量启用/停用筛选结果。只影响当前配置的草稿，保存后用于下一次启动。仍在配置但已不在全局库中的目录会标为“仅在此配置中”；重复路径保留原记录和额外字段，勾选会同步切换这些记录。拖入目录会收录到库并在当前配置中启用。失效的全局目录会提示并阻止新启用，原已启用条目仍可取消。

## 配置与存档

### 多个独立存档主机

使用内置 MCDK 和已验证的开发版 **3.10.0.436581** 时，可同时启动多个不同存档，分别绑定启动配置。每个主机有独立的游戏设置、模组运行目录、调试连接和日志；同一实际存档不能重复打开。控制台可切换运行中的存档，停止一个不会停止其他主机。设置中的“启用独立主机”默认开启；关闭后、其他游戏构建、自定义启动器及旧式源地图启动使用兼容单主机方式。已运行的旧会话不会被中途改成隔离模式。

独立运行环境保存在 `%UserProfile%\DgnGameToolkitHosts\`，存档本身仍在登记位置；运行环境通过受控目录入口访问原存档。首次使用继承原有游戏设置，之后保留该存档的独立设置并应用全局启动覆盖。不同存档可以使用同 UUID、同模块名的不同模组源码。若配置引用同一份源码，修改文件仍会影响所有使用它的会话；界面和 MCP 会提示共享目录，需要分别开发时请使用不同目录或工作副本。

AI 使用工具箱 MCP 的 `launch_world(worldId, instanceId, requestId)` 启动各自存档，再通过 `list_clients` 获取 **sessionId / generation**，分别执行代码、读取日志、热更新或停止。先核对 `toolbox_status.capabilities.isolatedWorldHosts` 和支持版本；`storageMode` 标明本次是否隔离，`sourceRoots` / `sharedSources` 用于核对源码范围。不要把默认 `mcdk_game` 连接当作任意主机。本功能是多个本地存档主机，对外联机分享继续使用现有联机页。

代码、日志和热更新按会话分别处理。桌面键鼠仍共享窗口焦点，多个 AI 应轮流调用 `mc_input`，沿用原 MCDK 的前台校验；独立主机不代表独立键盘鼠标。

每个存档可通过“功能配置 / 打开控制台 → 添加功能”保存最多 64 个按钮，类型包括单条游戏指令、给予物品、设置群系和客户端/服务端 Python 2.7 脚本。按钮可编辑、排序、启用/停用或删除；支持在 `_result` 中返回脚本结果。配置保存在存档库的 `worlds.json` 对应记录，不写入游戏 `level.dat`。

“设置群系”也可作为即时功能使用：下拉选择常用原版群系，或输入已加载的自定义群系标识符。范围包括脚下当前 16×16 区块、圆形（半径 0–32 方块）、矩形（X 长度和 Z 宽度各 1–64 方块），以执行时房主脚下方块为中心，不随视角旋转；偶数边长向负方向多一格。维度 ID 和整列高度从房主当前维度实时读取，也支持指定绝对最低/最高 Y。未加载区块或未知群系在修改前拒绝；分批执行，部分失败记录已确认范围并停止，不自动重试。此功能在当前已加载区块修改群系，不重新生成地形。旧 2D 群系仍影响整列，3D 表面群系仍遵循引擎向上延伸规则；草、水等颜色可能需要重新进入区域刷新。高度边缘使用逐坐标接口，避免原生体积接口将 Y 扩大到整段子区块。

群系功能直接调用原生接口，不再写入额外群系记录或挂接启动/区块加载恢复逻辑。旧版已经写入存档的群系记录保留，但新版不会读取或回放。游戏自身的正常保存机制不变。3.10.0.436581 独立实测中，只改群系可能在保存重进后还原，同一区块另有实际方块变化时则能保留；执行成功只表示当前修改成功，请重进核对持久化结果。工具箱不会通过额外改动地形来触发保存。

勾选“每次启动存档，玩家就绪后自动执行一次”后，以启动时的功能快照按卡片顺序执行；修改在下次启动生效。开发辅助模组由工具箱在启动时自动加载。自动操作最多等待 120 秒，失败后停止剩余操作，不因切页、重连或重载重复执行。指令的执行者及给予物品的接收者为该存档房主；指令自身的 `@a` 等选择器仍按游戏语义生效。超时或断线不自动重试，请先检查游戏内结果再决定是否手动执行。待执行的自动操作可取消，已经发给游戏的操作无法撤回。最近 100 条执行结果显示在控制台，并写入对应会话的脚本日志。

启动配置保存在 `%LocalAppData%/DaGuoNeko_GameToolkit/profiles/` 下，各套配置相互独立，支持 JSONC、未知字段保留、保存备份与外部修改检测。世界字段不允许写入启动配置，统一在存档设置中管理。首次打开新版会备份设置索引，将以前登记的项目配置导入为同名启动配置；原项目 `.mcdev.json` 保留，不会被移动或改写。

全局游戏程序保存在工具箱设置的 `GamePath`，可手动选择或从发现的版本中选择，自动保存。新配置及 `game_executable_path` 为空的配置在启动时继承全局路径；明确指定 EXE 的旧配置保留独立版本，可勾选“使用全局游戏程序”后保存来切换。首次升级备份设置索引，优先从旧空白客户端路径、再从已有配置中选取有效 EXE 作为全局默认，不改原配置。修改全局程序只影响之后的启动，已运行会话不变；已设置但失效的全局路径会明确报错，不悄悄换版本。

新建及复制导入的存档放在 `%AppData%/MinecraftPE_Netease/minecraftWorlds/DaGuoNekoGameToolkit/`；直接使用原目录的存档保留在所选位置。首页展示所有存档卡片，各卡片绑定自己的配置；更换绑定不会修改配置本身。首次启动新世界时生成数据，已生成世界的种子和世界类型不能修改；名称用于卡片显示。删除先移入回收站，支持恢复；清空包括搜索条件隐藏的回收站卡片。新建及复制导入的存档永久删除会删除其数据；原目录模式只移除登记和运行入口，始终保留原目录、进度和模组。删除中断会显示“删除未完成”，只能重试，不能恢复残缺存档。导入、删除、清空和恢复时请退出游戏。

存档页支持拖入文件夹或 `.zip`，也可在导入窗口中选择或拖入。文件夹默认“直接使用原目录”，游戏读写、进度保存和模组编辑都使用这一份目录；也可选择“复制导入（独立副本）”，保留原目录不变。ZIP 必须解压到存档库使用，其原文件不变。文件夹应直接包含 `level.dat`；ZIP 可包含外层文件夹，多份并列存档需分开导入。直接模式通过工具箱校验的目录联接提供游戏运行入口，拒绝重复登记和被替换的入口，原目录丢失时停止启动，不创建空世界；禁止重建或源地图覆盖。旧版已导入的副本保持独立，不会自动转换或覆盖原地图。

导入默认选择“自动匹配（存档自带模组）”：存档和模组清单校验通过后，自动为该地图创建并绑定一套独立的“地图名（自动匹配）”配置，继承全局游戏程序、不包含额外业务模组，地图自带包仍按原清单加载。没有现成配置也能导入；之后可在启动配置页编辑自动创建的配置。选择已有配置时继续使用该配置。“前去添加配置”会打开新建配置界面，并保留当前地图路径、名称、使用方式和选择；新建后可通过“返回导入存档”继续，默认选中新建的配置。无效源或复制/清单校验失败不会额外创建配置；极少数最终索引写入失败会保留已创建配置并明确提示。

ZIP 逐文件校验大小与 CRC，只写入新的存档 ID 目录，拒绝路径越界、目录链接、Windows 特殊路径、重复/冲突路径和加密压缩包。支持普通存储/Deflate ZIP，最多 100000 项、单文件 2 GiB、总解压量 8 GiB。失败后若已创建卡片，会保留为“复制未完成”，不能启动，可移入回收站后重试。导入完成后保持原始文件内容，并从 `level.dat` 读取世界设置。

导入配套地图时，会记录 `world_behavior_packs.json` / `world_resource_packs.json` 中原本启用的包；缺少标准清单时兼容网易清单名。内置行为包与资源包自动进入本次运行快照，无需逐个收录到模组库，原启动配置不改。建议绑定不含额外业务模组的配置；额外模组仍可加载，同 UUID 的外部副本会明确报冲突，缺失或版本不匹配的引用不会被静默跳过。未列入原清单的目录不会自动启用。

首次启动会在实际使用的存档中为旧 `pack_manifest.json` 补充同 UUID/版本的标准描述，并把内置包整理到该存档的 `.toolbox-packs` 下，由启动器统一注册，避免 Windows 开发版把世界内包名误加到 Python 导入路径。直接模式会在所选原目录执行这一步，复制模式仅整理副本；旧描述文件保留。此后从卡片“打开目录”进入 `.toolbox-packs/behavior_packs` 或 `resource_packs` 编辑代码或资源，无需重复导入。原清单单独保存，运行清单重写不会丢失原启用顺序；请保留完整存档目录（包括 `.toolbox-packs`）。旧版本若已经覆盖了原清单，需要从未修改的原地图重新导入。

存档自带模组默认允许热更新，直接模式和复制模式均适用。存档绑定的启动配置开启“自动热更新 Python 模组”后，保存已加载脚本的修改会由工具箱监听，再通过游戏原生增量更新接口处理，无需退出游戏；自动匹配新建配置默认开启，已有配置保持原开关。关闭自动更新时，可在运行日志或游戏调试页点击“热更新脚本”。同路径外部模组条目显式关闭热更新时仍保留该选择。JSON UI 等资源遵循各自的自动更新开关，并不因为 Python 自动更新开启而全部自动重载。热更新用于已加载代码，不能代替重新执行模组启动初始化；新增模组入口或需要重新初始化时仍使用重载功能。需要用新版工具箱启动一次游戏，已有旧进程不会被中途改写运行配置。


每次启动都会在 `%LocalAppData%/DaGuoNeko_GameToolkit/runs/` 下生成独立运行快照；之后修改配置只影响下一次启动。联机客户端使用各自的数据目录准备模组，避免清理其他实例正在使用的运行文件。运行快照及客户端数据保留，不自动删除。菜单启动不自动选中世界，仍由你在游戏内手动联机。

空白客户端只使用独立玩家名、游戏程序和内部菜单运行数据，不继承任一配置的模组、调试模组、热更新或 MCP 设置，不保存为启动配置。默认采用全局游戏程序；已有存档运行时优先匹配该存档的版本，便于联机。全局未设置时才依次尝试最近会话、已有配置中的有效程序和已安装版本。没有启动配置也可以使用自动发现；找不到程序时会提示，可在“设置 → 全局游戏程序”中指定。

菜单客户端（包括空白客户端和配置卡片“启动客户端”）会在启动时应用你填写的玩家名，支持单字母和中英文名称，多开分别生效。设置成功会在该会话日志中提示。此操作只针对本次启动的游戏进程，不改共享 options.txt、不改账号 ID，也不自动加入世界。需要内置 MCDK 的会话连接和受支持的 Windows x64 网易开发版；名字设置失败或游戏接口不兼容时会明确报错并停止新客户端，避免卡片显示指定名、游戏却使用随机名。

已支持多个独立存档主机和多个菜单客户端；独立主机目前要求内置启动器与开发版 3.10.0.436581。兼容模式保留单主机限制和共享目录的启动冲突检查。同一存档不能重复打开，不接管外部游戏。开发版 3.10.0.420447、3.10.0.436581 已验证菜单名及联机后服务端收到的玩家名；其他版本仍需核对接口兼容性。

## 启动前游戏设置

启动冲突按程序完整路径和开发版标识检查。与测试版同名、但位于独立安装目录的正版客户端不会仅因 `Minecraft.Windows.exe` 这个名字阻止测试端启动。已有配置指定的程序、其他 MCStudio 开发版本及脚本模式开发版仍纳入共享测试数据保护；无法读取进程路径时会明确报错。当前已验证发烧游戏平台正版使用 `MinecraftPC_Netease_PB`，开发版使用 `MinecraftPE_Netease`。设置覆盖不会写入正版的数据目录。

侧栏“游戏设置”用于编辑启动前的网络、画面、声音和鼠标选项，所有启动配置及空白客户端共用。需要网络调试时，点击“启用完整网络堆栈”，保存后再启动游戏；这会将 `dev_connection_quality` 设置为 `1`，即游戏中的“完整的网络堆栈已开启－无限制”。弱网模拟另有 4G、3G、慢、非常慢档位，会主动增加延迟与丢包。已进入世界后网络模式可能无法切换，需要退出游戏后重新启动。

页面支持搜索、查看文件当前值、逐项选择是否覆盖、定位 options.txt 和打开备份目录。模板保存在工具箱设置目录的 `game-options.json`；保存模板不立即修改游戏文件。启动前只更新选中的配置项，保留未知字段、原有换行和其他设置，备份放在 `game-options-backups/`。取消覆盖表示以后沿用文件里的值，不自动撤销之前已应用的设置。未保存草稿切页保留，启动前会提示保存。

数值框可直接编辑，修改后自动启用“启动时覆盖”，无需先勾选。清空重填和小数输入过程会保留，保存时检查格式与范围；取消勾选会恢复显示游戏原值（文件中没有该项时显示建议值），并停止启动覆盖。渲染距离以区块输入，保存时换算为游戏文件使用的格数。

实测开发版 3.10.0.420447 即使在独立 APPDATA 的菜单客户端中，也读取 `%AppData%/MinecraftPE_Netease/minecraftpe/options.txt` 的真实用户路径。这份游戏设置由多个客户端共享：有游戏运行时，若文件需要改变则拒绝启动并提示先退出；已符合模板的情况下无需改写，可继续多开。修改游戏 EXE 或给客户端设置独立 APPDATA，不代表这些设置已隔离。全新环境未生成 options.txt 时，先启动一次游戏，再使用本页启动覆盖。

真实验证：启动前设置 `dev_connection_quality:1` 后，开发版菜单显示完整网络堆栈；随后已成功进入新建测试世界，游戏内该项虽然变灰，仍显示“完整的网络堆栈已开启－无限制”，日志确认网络连接模式。灰色表示当前不能切换，不代表已关闭。各弱网档位的实际数据包延迟、丢包比例尚未测量。测试后恢复原网络设置并归档诊断世界，现有用户存档未修改。

## 日志

标题栏可切换“脚本日志”和“游戏调试日志”。后者实时接入游戏原版的 `ContentLog` 内容日志和 `Debug_Log` 引擎日志，日志类型中可分别筛选。按所选客户端的 PID、启动器归属和实际打开的文件句柄识别来源，多开时不按文件时间猜测。请先在游戏“设置 → 创作者”开启内容日志文件，或在工具箱“游戏设置 → 游戏调试日志”保存启动覆盖。游戏的文件输出可能有缓冲，工具箱只能在原版实际写入后读到。

运行日志默认打开“脚本日志 → 全部”，直接显示 print、Python 和 MCDK 输出；切换到“游戏调试日志”时默认显示“重要日志（警告/错误）”。按内容日志的结构化级别识别警告/错误，不因普通信息正文里出现 error 一词就把它算作问题；普通信息、引擎日志和脚本输出可在类型菜单或频道按钮中查看。重要视图去掉原版行首时间戳，将分类、级别和正文完全相同的消息合并为一项并显示 ×次数，避免重复刷屏；计数来自整份所选会话归档，保留首次出现的位置。这里只改变显示，不删除归档；搜索和分页按合并后的问题计数，导出仍包含完整原始记录。

搜索框常驻日志主界面，输入关键词检索当前所选频道、会话的整份已保存归档，先匹配再分页，不限于实时窗口末尾 2000 条。支持匹配文字高亮、大小写切换、上一条/下一条匹配行、Ctrl+F 聚焦、Enter/Shift+Enter 定位及 Esc 清除。查询按字面文字匹配，`*`、`[` 等字符不作为正则表达式；每行最多高亮 64 处。每页最多显示 2000 条匹配，可用“更早记录 / 较新记录”翻页；“全部记录”可查看较早归档，“返回实时”退出查询。当前运行会话的最新查询页会定期刷新，历史或较早页保持稳定，可手动刷新。

内容/引擎/会话事件保留各自的实时缓存，避免大量引擎输出挤掉内容错误。“重要日志”“错误与异常”以及历史模式都从整份归档筛选。重要视图可用“查看原始内容”切回逐条实时查看。清空显示只用于实时模式；查询可以找到已清空显示但仍保存在归档中的条目。搜索范围是工具箱已经保存的归档，仍受采集起点、50 MiB 归档上限和游戏写盘缓冲影响，不代表所有原始文件内容都已采集。

游戏调试日志独立归档到 `%LocalAppData%/DaGuoNeko_GameToolkit/logs/game/`，切换频道后历史、导出、清空显示及历史删除都作用于该频道；删除的是工具箱副本，游戏原始文件保留。提供“打开游戏原始日志目录”便于核对。首次连接大日志只读取每个文件末尾 1 MiB，之后有界增量读取，不一次性载入整份文件。进程归属不明、权限不足时显示状态；不会混用另一客户端的日志。归属识别与增量读取实现见 `DesktopUI/electron/domains/game/game-logs.cjs`；本机排查日志不随仓库发布。

日志会话卡片固定在上方单行，可横向滚动，日志铺满下方剩余区域。跟随由滚动位置自动控制：滚动到底部就跟随最新，向上滚动就暂停跟随；不再提供手动跟随或暂停显示按钮，日志始终接收并保存。追加日志或窗口尺寸变化时尽量保留正在阅读的行及位置；最早记录超过 2000 条显示上限被移出后，可从历史查看。点击会话卡片或切换历史会默认从底部查看，搜索/类型筛选条件保留。右侧仍支持历史记录、源文件定位、清空显示和导出，收起侧栏保留状态。颜色沿用官方日志工具的深色规则，着色不修改原始文本，网址与 HTML 字样仅作为文本显示。

历史日志保存在 `%LocalAppData%/DaGuoNeko_GameToolkit/logs/`，每个会话单独记录，最多 50 MB；窗口显示末尾 2000 条，历史列表显示最近 100 次。“清空显示”保留磁盘历史，导出包含清空前的记录。目录中的文件不自动删除。日志分别显示游戏进程和 MCDK 的退出码，启动器返回 0 不代表游戏未崩溃。

日志按每次启动的会话保存，不与存档一一绑定：存档主机会记录 worldId，菜单/联机客户端可能没有存档关联，所以删除存档不会自动删除日志。在“运行日志 → 展开日志设置 → 日志会话”中，可“删除选中历史日志”或“清理全部已结束日志”。清理全部包含最近 100 条之外的旧记录及残留的日志/索引；确认弹窗显示数量和大小，只删除确认范围内的记录，期间新产生的日志保留。运行中、启动中或停止中的会话受保护，永久删除前应先导出需要保留的日志。删除同时清空相应已结束会话的显示缓存，但保留会话卡片、存档和启动配置；如部分文件无法删除会明确报告，可重试清理残留。

会话卡片使用紧凑两行显示，PID 和启动时间悬停可看。已结束的会话右侧有删除按钮，只移除卡片、保留历史日志和运行目录；运行中的会话不能删除。删除当前卡片会优先切换到仍运行的会话。日志标题栏“一键到底”可立即滚到当前筛选结果底部并恢复自动跟随。

## 游戏调试

通过启动配置启动存档或客户端时，工具箱自动加载开发辅助模组，已有配置中关闭该选项也会在本次运行中自动启用；保存或复制配置时统一写为启用。普通“空白客户端”仍不加载模组。进入世界后打开“游戏调试”，待会话显示“调试就绪”即可操作；连接不会使用或覆盖 VS Code 的 Host Bridge 凭据。

“设置 → 全局热更新与重载快捷键”统一设置脚本热更新、重载世界、Add-on 和 Shader 的单键，所有启动配置共用。点击输入框后按键，Backspace/Delete 清除，自动保存。首次升级备份设置索引，从第一套具有有效显式按键的旧配置导入绑定；找不到时脚本使用 R，其他留空。旧配置文件保留，启动时旧按键统一由全局值覆盖，其他未知调试选项保留。默认开启“在其他游戏界面也响应快捷键”，可自行关闭。按键仍需游戏接收输入及加载开发辅助模组，不是 Windows 系统级快捷键；修改在下一次启动游戏时生效。

“运行日志”的会话卡片下方及“游戏调试”会话选择下方提供“热更新脚本”“重载游戏”“重载资源和游戏”。日志页按钮只作用于当前选中的实时日志会话，历史模式隐藏。按钮通过自己的调试连接发送请求，不模拟游戏按键，不经过 HUD 按键过滤，但仍依赖游戏内 IPC 和主线程调度，暂停/未就绪状态下可能不能立即执行。重载游戏重新加载当前世界运行环境，不重建存档；重载资源会同时刷新 Add-on 数据。重载前需确认并保存游戏进度，性能采样或 UI 拾取期间先结束相关操作。重载接口返回仅表示请求已接收，需等待游戏重新就绪；超时或断开不自动重发，也不代表游戏未执行。

重载与配置来源：热更新脚本、重载游戏和重载资源沿用本次启动来源，不会自动切到其他 Git 工作树。运行日志、游戏调试和存档控制台可查看实际模组目录；工具箱按钮及 MCP reload_client 在执行前核对已保存配置。模组路径、启用列表或脚本热更新设置变化时会提示并阻止旧快照重载，存档主机可点“按最新配置重启”。请先保存游戏进度，勾选确认后只停止目标主机，并重新读取已保存配置启动同一存档；其他主机保留。快速测试按该存档已保存的勾选列表重启。确认期间配置再次变化、路径缺失或停止失败会中止，不自动回退旧来源。未保存的配置草稿不应用；游戏内原生重载快捷键仍沿用原生路径，不会重读工具箱配置。

工具箱“热更新脚本”按钮采用桌面侧增量筛选：按启动时启用且允许热更新的行为包扫描源码，去重目录，排除嵌套备份包，只选游戏已经加载且修改时间晚于加载基准的模块。由游戏自带的网易 `common.utils.xupdate.update` 执行，成功后记住文件签名，避免反复更新同一改动；每批最多 4 个模块，超过 256 个变更建议重载游戏。同名来源冲突、文件仍在写入或异常回包会停止并报告，不自动回退全量扫描。传输仍经过 MCDK，这不是 MCStudio 私有协议的复刻；游戏内快捷键和 MCDK 自动热更新仍沿用其原生路径。单个模块的更新成本仍可能较高，不能保证所有更新都无卡顿。

- **代码执行**：选择客户端或服务端，编写 Python 2.7 代码，点击“执行”或按 Ctrl+Enter。使用 `_result` 返回值，`print` 输出见运行日志。代码草稿与最近 30 次结果在本次打开工具箱期间保留；请求超时不代表游戏代码已被撤销，不自动重试。
- **调试函数**：扫描当前会话配置所启用模组内的 modMain.py 所在脚本包的顶层函数，收藏后配置必填、可选或固定 JSON 参数，选择执行端调用。扫描不导入源码。收藏存入工具箱设置目录，不写入模组源文件。
- **UI 调试器（侧栏独立页面）**：使用说明见下节。它与“游戏调试”共享会话选择，界面布局和操作状态独立保存。
- **Python 性能**：基于 Yappi 采样客户端、服务端或两端，选择 CPU/WALL 时间，查看调用次数、总耗时、自身耗时和调用关系。
- **Python 内存**：基于 tracemalloc 比较前后快照，显示分配增量与调用栈。客户端与服务端共享进程内存；可选在手动结束前执行 GC。
- **Native 性能**：按所选游戏 PID 自动匹配 8086–8105 的 Tracy 端口，采集线程、函数热点和调用树，可导出 `.tracy` 原始数据。需要游戏支持 Tracy 0.11.1；没有端口或协议不兼容时显示具体错误。

采样时长为 1–300 秒，每个会话同时进行一项采样。完成后自动保存到 `%LocalAppData%/DaGuoNeko_GameToolkit/debug-reports`，可导出 JSON；内存跟踪有超时释放。不同游戏版本可能缺少 Yappi、tracemalloc 或对应 UI 接口，工具箱会显示运行时错误，不以空的成功结果代替。

日志会分别记录 MCDK 启动器与 Host Bridge 通知的 Minecraft 游戏进程退出码。启动器返回 0 不能单独证明游戏没有崩溃。

- 选择游戏后点“连接所选游戏”，根据 Host Bridge 游戏 PID 自动匹配 8086–8105 端口，连接前校验监听归属和占用。同一游戏已有官方 Tracy 或 Native 采样时拒绝重复连接；不抢占、关闭或嵌入用户原来打开的分析器。
- 没有游戏也可“打开分析器”或“打开 .tracy 文件”。文件由系统选择框授权，路径直接作为单独参数交给官方程序，不修改原文件。协议或采样文件版本不兼容时，以官方窗口提示为准。

- 保存使用官方界面的 Save / Save trace。关闭分析器只向本工具箱新建的窗口发送关闭请求；若有官方保存提示，在独立窗口处理。退出工具箱时将分析器恢复为独立窗口，保留已收到但未导出的采样。建议退出游戏前先停止并保存采样，游戏提前退出可能导致尾部数据不完整。

## AI 多客户端 MCP

存档卡片与控制台提供“快速测试”：从全局模组库勾选目录后直接启动，使用程序默认参数与已保存的全局游戏程序、窗口大小、热更新按键，不生成启动配置，也不修改原绑定配置。该存档上次的勾选会被记住，原配置已移除时仍可使用。地图进度及自带模组保留，调试辅助模组自动加载；勾选目录默认开启脚本热更新。模组库发生变化或所选目录不可用时会阻止启动，重新打开选择后再试。此入口使用已保存的全局游戏设置，不自动保存其他页面的未保存草稿。

游戏窗口标题自动显示“Minecraft · 地图名 · 玩家名”，主菜单显示“Minecraft · 主菜单 · 玩家名”。游戏就绪后通过所属会话读取实际名称，工具箱的自动入房也保留房主地图名；无法读取名称的已入房客户端显示“Minecraft · 联机游戏 · 玩家名”。后台仅同步所属游戏窗口的标题，缩放导致原版标题恢复时会再同步，不改变窗口位置、大小或焦点。固定保留 Minecraft 前缀，以兼容 MCDK 按 PID 和窗口标题查找游戏的规则。

“设置 → 默认游戏窗口大小”可保存常用尺寸或自定义宽高，初始为 1280×720。用于下一次启动普通存档、空白客户端；关闭开关后使用游戏原有尺寸。启动配置中显式设置的 `window_style.fixed_size` 优先，其他窗口样式保留；自动加入本机房主的客户端继承房主本次启动快照，不受之后修改的全局尺寸影响。设置不会调整已经运行的窗口，也不会改写各启动配置文件。

本机多人测试默认采用“存档房主 + 多开客户端”，不要进入“联机房间”创建分享、邀请码或隧道。“联机房间”用于明确要求的异地朋友远程联机。

本地测试流程：先 `toolbox_status` / `list_clients` 核对已有主机和 `worldId`；没有合适主机时用 `launch_world` 启动目标存档，等待 `game_ready`。随后每位测试玩家调用一次 `launch_joined_client`，显式传入同一个目标 `hostSessionId`、不同玩家名及各自的 `requestId`，轮询 `autoJoin.phase=joined` 后再测试。多个存档主机各自配对客户端，不能取列表第一项或默认 MCDK 连接代替目标确认。同一次启动超时只复用原 `requestId`；需要停留主菜单时才使用 `launch_client`。

“设置 → AI 多客户端 MCP”可以开启或关闭本机连接、查看状态和复制通用 MCP 配置。服务使用 Node.js 22 或更新版本，通过 stdio 接入 AI；工具箱关闭时仍能列出工具，并通过 `open_toolbox` 打开最近登记的版本。关闭 MCP 不会关闭游戏，已接收的操作会等待完成。

- `toolbox_status` / `list_clients`：返回本次工具箱实例 ID、各客户端会话 ID、进程、连接代次和当前能力。
- `list_launch_profiles` / `list_worlds`：查询可用启动配置与存档绑定。
- `launch_client`：`blank` 是原来的无模组空白客户端；`debug` 仅加载开发辅助模组；`profile` 使用指定配置。都先停在主菜单，之后手动联机，支持独立玩家名。`debug` 和 `profile` 的本次运行开启调试模组与 MCP，不修改保存的配置。
- `launch_joined_client`：指定 `hostSessionId` 和新玩家名，新开客户端并后台自动加入这个本机存档主机。继承房主本次运行快照中的游戏程序、模组和窗口设置，不采用之后修改过的模板。向本次新客户端定向发送一次 Enter 打开初始游戏列表，再通过官方 OreUI 数据读取完整房间 ID 并调用 joinLanServer，不使用截图、OCR 或鼠标坐标。以实际 LevelName、房主和保真的 NetherNet 标识共同核对目标。`list_clients` 的 `autoJoin.phase` 提供 waiting_menu / finding_room / joining / waiting_assertion / verifying / joined / needs_attention / failed；只有房主收到与新客户端真实玩家 ID 匹配的随机消息回执才标记 joined，启动返回或 game_ready 都不等于成功入房。
- `launch_world`：按存档绑定配置启动主机，本次运行开启调试模组与 MCP；支持已验证引擎的多个不同存档，返回各自 sessionId/generation。检查 storageMode 与 sharedSources，避免混用会话或共用待修改源码。
- `client_logs`、`execute_client_code`、`reload_client`：读取指定客户端日志、通过对应 Host Bridge 执行代码或热更新/重载。游戏内代码必须等进入世界且能力就绪。服务端代码操作的是该客户端连接的服务器。
- `list_client_mcdk_tools` / `call_client_mcdk_tool`：先发现该客户端实际支持的 MCDK 工具，再调用截图、输入、UI 调试等功能，图片保留 MCP image 格式。转发前校验端口监听进程属于该会话，不回退到默认主游戏。重载统一使用 `reload_client`。
- `close_client`：`confirmed=true` 后只关闭指定会话；请先保存游戏。`remove_client` 只移除已结束卡片，保留日志和存档。

启动前先查询 `toolbox_status`，传入 `instanceId` 和自己生成的 `requestId`。同一次启动超时重试必须复用同一 ID；工具箱重启后先查现有客户端，不能直接重试。代码、输入和重载请求超时后结果可能已经生效，不自动重放。调试操作必须明确传入 `sessionId` 与最新 `generation`，不依赖界面当前选中的客户端。

原来的 `mcdk_game` MCP 保留，适合既有主游戏工作流。新 MCP 的客户端使用独立端口；遇到默认端口被占用时只改变本次运行快照。原 MCP 不会自动切到其他客户端。工具箱只管理自己本次运行拥有的进程，不接管旧工具箱或外部启动器的游戏。

Codex 配置示例（放入用户 `config.toml`，不要替换其他 MCP；将 `<用户名>` 替换为自己的 Windows 用户名，或直接从工具箱复制实际配置）：

```toml
[mcp_servers.daguoneko_toolbox]
command = 'C:\Program Files\nodejs\node.exe'
args = ['C:\Users\<用户名>\AppData\Local\DaGuoNeko_GameToolkit\mcp\server.cjs']
startup_timeout_sec = 15
tool_timeout_sec = 120
```

工具箱启动时会更新数据目录下的稳定 stdio 文件和可执行程序登记路径，所以配置不依赖某次打包目录。连接凭据只保存在本地数据目录，不显示或复制给 AI。需要切换新版本时先保存并关闭旧工具箱的游戏；旧版工具箱无法接受新的原生自动联机请求；本次后端接口版本为 3，其他既有工具仍兼容。当前 Codex 需重载 MCP 服务才能使用更新后的工具说明。

自动联机要求房主已经进入存档、开启局域网并加载 MCDK 开发辅助模组。目前原生方式已适配开发版 **3.10.0.420447、3.10.0.436581**，启动前校验游戏程序哈希；其他版本或结构不匹配会明确拒绝，不尝试内存写入。无需安装 OCR 语言包、Python 或 Ghidra。工具为每个新客户端建立独立的本机回环调试端口，完成或失败后封闭通道并恢复临时调试标志；不保存这项临时标志，也不修改游戏 EXE 或配置模板。启动过程中请让新客户端保持初始菜单流程。目标身份不唯一、房主重载或网络加载失败时停止操作。后台加入最多等待约 120 秒（单次系统调用另有超时边界）。检测到原生断言后进入 waiting_assertion：保留客户端和弹窗，暂停游戏操作，不自动点击忽略；用户在本次等待期限内处理弹窗后继续验证，不重复发送入房请求。到期仍未处理则进入 needs_attention，封闭原生通道并保留客户端供手动处理，不表示入房成功。初始化操作边界上遇到断言且无法安全续接时也会保留客户端并报告 needs_attention。断言等待不延长原生通道或房主验证监听的生命周期。取消、房主/客户端代次变化、进程归属异常及通道无法封闭仍会停止本次新客户端；其他客户端和房主保留。toolbox_status.capabilities.autoJoinAssertionPolicy=pause_preserve 表示后端具备这项行为，旧运行实例需重启新版工具箱生效。关闭客户端会取消该次加入，正常退出工具箱会等待清理。不要通过换 requestId 反复重开失败客户端，应先排除失败原因。

`joined` 记录的是本次加入验证，不持续限制玩家之后手动离开/切换世界。验证监听只存在于房主内存，完成后移除，并有游戏计时器兜底清理；校验机制不写存档或模组源代码，新玩家加入仍可能产生正常的玩家数据。MCP 的 IPv6 回环监听识别已修复，支持当前主客户端的 `[::1]:19133`。

## UI 调试器

1. 从侧栏进入“UI 调试器”，选择已就绪的游戏会话。点击右上角“展开”，即可打开可独立移动、缩放的调试窗口，与游戏并排使用；窗口会自动读取屏幕、开启双向选中。也可留在工具箱页面，手动“读取屏幕”。
   独立窗口只保留控件树和控件属性。游戏会话、UI 屏幕、双向选中、边界显示与自动刷新设置都留在工具箱的原页面，展开后仍可在原页面控制；切换屏幕遇到未应用草稿时，在原页面确认。
2. 左侧按需展开控件树；搜索与类型筛选只作用于已经读取的控件，不递归扫描整个游戏界面。较大的子节点列表分页加载，直接定位到中间页后也可向前补读。游戏中新增或删除控件后，选中父控件并点击“刷新子控件”更新其列表。
3. 开启“双向选中”后，点击游戏控件会自动定位并展开对应树节点；点击树节点立即显示选中，属性在右侧异步读取，游戏高亮先于属性查询执行。读取期间不会展示上一个控件的属性。每行眼睛按钮先反馈显隐操作，再以游戏回读为准；失败会撤回临时图标并提示，超时后应刷新确认实际状态。连续选中优先处理最后一次点击，旧回包不会覆盖新选择；未变化的树节点复用，窗口之间只同步变化的数据。
4. 右侧“属性一览”用中文显示类型、位置、大小、可见性、文字等当前值，支持搜索。需要修改时切到“分组编辑”：位置、大小、颜色使用分量输入，开关使用复选框，文本直接编辑。点击该属性的“应用”按钮写入；“重置”只丢弃草稿。“全部属性”保留原始数据。完整路径定位、面包屑、前进/后退和复制路径用于快速导航，左右分隔条可拖动调宽。
5. 写入前在游戏中核对该属性是否仍等于上次读取值；发生冲突则拒绝覆盖并保留草稿。成功后显示实际回读值，可撤销当前控件最近的修改；撤销同样不会覆盖游戏随后产生的变化。最多保留 20 条撤销记录。若请求超时，先刷新确认实际值，不要假定修改未执行。
6. 在工具箱原页面点击“收回工具箱”，或直接关闭独立窗口，会将树、选中项、属性草稿交回主页面，同时停止该窗口的拾取；不会停止游戏。展开期间原页面保留设置与窗口控制，控件检查和编辑由独立窗口执行。若尚有属性写入请求，等回读完成后再收回。留在工具箱内调试时，切离 UI 页面也会停止拾取。开启自动刷新后每约 1.5 秒读取选中控件；有未应用草稿、正在编辑或另有请求时暂停刷新。

同一会话切页保留树、选中项、搜索和属性草稿；不同连接版本使用不同缓存，旧请求不会覆盖新选择。切换控件时有草稿确认，退出应用时也会提示未应用修改。重连后遗留的草稿可用“清除旧会话草稿”丢弃。

眼睛按钮直接反转游戏中的最新可见性；撤销仍会检查后续变化。隐藏的父控件会影响子控件的实际显示，眼睛表示控件自身的可见属性。以上修改只作用于当前游戏运行，不保存到项目 JSON。运行时自动布局、绑定或动画也可能再次改变属性，必要时回到项目源文件修改。
