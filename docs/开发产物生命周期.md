# 开发产物生命周期

## 归属

临时脚本、视觉截图、验收报告、测试存档副本和失败日志都必须属于一个任务目录：

```text
.miao/work/<任务ID>/
  manifest.json
  scripts/
  outputs/
  data/
  logs/
  backups/
```

任务 ID 使用 `<功能>-<YYYYMMDD-HHmmss>`。目录中的 `manifest.json` 记录 `id`、`kind`、`createdAt`、`expiresAt`、`status` 和 `preserve`。没有清单的目录是孤儿产物，清理工具只报告，不自动删除。

一次性脚本可以先放 `.miao/scripts/`，临时记录放 `.miao/notes/`。脚本经过两次以上复用或成为稳定回归后，移动到 `DesktopUI/scripts/` 或 `DesktopUI/tests/` 并提交。长期有用的结论整理到 `docs/`，不把原始聊天、机器路径和验收流水账放进正式文档。

## 保留时间

普通验收任务默认保留三天。任务成功、失败或中断都从 `expiresAt` 开始计算。需要长期保留的任务把 `preserve` 设为 `true`，并在清单或对应正式文档中说明原因。

运行中的任务、用户存档、模组源码、`.env`、`.mcdev.json`、便携工具、依赖缓存、`DesktopUI/runtime/` 中的可复用运行文件和发行资产不属于三天清理范围。

清理命令：

```powershell
Set-Location DesktopUI
npm.cmd run clean:dev
npm.cmd run clean:dev:apply
```

第一条只列出过期任务、系统文件和孤儿目录；第二条才删除有清单且已过期的任务，以及 `Thumbs.db`、`.DS_Store`、`desktop.ini`、`ehthumbs.db`。删除前应确认没有运行中的游戏、Electron 测试或外部工具使用目标目录。

## 目录边界

| 内容 | 位置 | 处理方式 |
|---|---|---|
| 正式测试与固定夹具 | `DesktopUI/tests/`、`DesktopUI/tests/fixtures/` | 提交 |
| 正式维护脚本 | `DesktopUI/scripts/` | 提交 |
| 临时任务产物 | `.miao/work/<任务ID>/` | 三天后按清单清理 |
| 一次性脚本 | `.miao/scripts/` | 可见；复用后内化 |
| 临时笔记 | `.miao/notes/` | 可见；有长期价值才进入 `docs/` |
| 工具和缓存 | `.miao/tools/`、`.miao/cache/` | 忽略；不按三天清理 |
| 构建、发行和 UI 输出 | `DesktopUI/dist/`、`DesktopUI/release/`、`.miao/work/` | 忽略或按任务清单清理 |
| 可跨设备开发环境 | `.env`、`.env.example`、`.env.local`、`.vscode/`、`.mcdev.json` | 默认可见；不得写入真实密钥 |

每个开发窗口结束自己的任务前，都必须完成必要验证并运行 `npm.cmd run package`，生成当前版本的最新本地 Release。它是本窗口的收口证据；本地出包不是 GitHub Release，`sourceDirty: true` 的包只能用于本机验收，不能交给 `release:publish`。

本地包版本跟随 Git 版本记录和用户已确认的版本计划，详见[开发指南：Git 提交与版本](开发指南.md#git-提交与版本)。`package.json`、锁文件、README 和 Release Notes 必须一致；正式发布还须匹配 Git 标签及发布资产。默认不升版，每次提升前必须取得用户对目标版本的明确同意；任务完成、提交合并、本地出包或已有标签都不能代替升版确认。

正式发布必须先完成版本、Release Notes、干净提交、标签、GitHub Actions 资产和 `.sha256` 校验，不能把本地包当成正式发布。

`npm.cmd run package` 开始前会自动清理历史发行物，只保留当前版本的标准发行目录、ZIP 和 `.sha256`。正在运行的发行目录和对应进程会暂时保留，不能覆盖；进程退出后，下次出包会删除旧的 `build-*` 目录。需要单独检查时运行 `npm.cmd run clean:release` 预览，确认后运行 `npm.cmd run clean:release:apply`。不把旧包无限期堆在 `release/`。

每个开发窗口结束前必须运行 `npm.cmd run package`。它会先清理旧的本地产物，再生成当前版本的最新本地 Release；当前发行目录被占用时允许暂时存在一个 `build-*` 目录，进程退出后由下一次出包收口。
