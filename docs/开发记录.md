- 在 0.1.8 游戏版本选择、能力表及来宾构建锁定的基础上，整合哈希已核验的开发版 3.10.0.448891 主机与来宾隔离支持，保留已有构建边界。
- 多开失败明确报告开关、自定义启动器、旧式源地图、未登记构建或已有共享兼容会话；控制台和 MCP 提供运行中的实际隔离原因。已有共享主机必须先保存退出再重开，不能靠修改设置中途升级。
- 自动加入保留所属游戏进程初始化完成记录的检查，叠加 448891 新进程 25 秒最小冷启动输入等待；旧构建、同进程重连、总入房期限和原生租约保留原边界，期限到达后不得继续发送输入或加入请求。初始化记录及最小等待不等同于菜单语义就绪。
- 修复空闲主菜单的引擎日志缓冲未刷新摘要末尾时，初始化检查一直等待的问题；使用已完成启动任务的摘要开始或结束记录，仍核对 PID 和启动身份。发布测试临时目录清理增加有界退避，处理短暂文件占用，不跳过更新安装断言。
- 本轮整合后实机：448891 新建两张地图，四个进程使用独立运行与下载目录，同 UUID/同脚本名模组分别加载；UI 和 MCP 分别入房，房主玩家名单正确。改变测试实例的全局程序不影响来宾构建锁定；A 组热更新、关闭后 B 组继续可用，测试进程已清理。
- 本机完整服务回归首次 349 项中 348 项通过、0 跳过，未改动的 Windows 进程枚举探针在 10 秒超时；补充的日志与输入检查 22 项通过。最终发行包由版本发布流程构建并验收，异地网络不在本轮验证范围。

## 2026-10-27 0.1.8 游戏版本选择与联机状态

- 设置与启动配置增加游戏版本下拉框、自动联机/手动启动筛选和可展开的能力表；显示实际 EXE 指纹对应的能力，目录名不能冒充受支持构建。游戏发现、隔离服务、OreUI、MCP 与网络助手构建名单共用版本登记表。
- 本机来宾锁定所选房主的启动构建。主机运行后切换全局游戏程序不会改用新版本；游戏文件在准备期间变化、主客机指纹不一致时停止新启动，保留其他会话。
- 运行日志在进程停止后继续显示“加入失败”“需要处理”或“入房已验证”，目标存档与错误详情仍可查看。
- 单机实测发现冷启动可能在固定菜单等待时间结束后才完成初始化。自动加入现等待所属进程的引擎初始化完成记录，再发送一次菜单操作；本机与远程入口复用检查，总期限、进程校验和不重放输入规则保留。
- 本轮构建、版本选择/日志专项 UI 通过，最终完整服务回归 **343/343**，无跳过。此前更新安装夹具清理出现一次 Windows `EBUSY`，单独复测及最终完整回归通过，未修改更新器或放宽检查。
- 实机使用新建测试存档及 `3.10.0.436581`：房主和来宾成功 `joined`，服务端收到来宾；修改测试实例的全局程序后仍匹配房主构建，两个独立目录互不复用，停止来宾保留房主，最终测试进程全部停止。
- `3.10.0.420447` 保留原有自动入房登记，完整隔离尚未开放；本轮未取得该构建，不能据另一构建结果宣布验证通过。异地樱花联机不在本轮验收范围，发行包由本次 0.1.8 发布流程构建。

## 2026-10-26 0.1.7 本机来宾选择主存档

- 存档页新增“启动联机客户端”，控制台提供“加入此存档测试”；选择明确的运行主机会话和不同玩家名，日志显示目标与验证结果，主机退出不自动换图。
- 来宾继承房主本次运行快照，兼容没有永久启动配置的快速测试主机，并阻止并发启动同名玩家。
- 后启动主机的原生发现通过所属进程的回环 UDP 端点定向转发，仍保留完整房间标识、连接代次和房主回执校验；不创建隧道，不更改防火墙。
- 已支持构建的定向来宾使用独立 Known Folder 环境与下载缓存，源码按所选房主复用，避免不同测试组同 UUID 包相互覆盖。
- 实机验证：开发版 3.10.0.436581、新建独立地图、两主机两来宾，分别经全局选择器与存档控制台入房；四个进程各有独立模组/下载目录。两组使用同 UUID、同模块名的不同代码，玩家名单各自正确；仅热更新 A 组后 A 双端变化，B 双端不变。测试不涉及原存档或远程隧道。
- 构建、选择器真实 IPC/UI、UDP 配对/身份/清理及来宾目录隔离测试通过。本机完整服务回归 335 项中 334 项通过；未改动的 Windows 进程枚举探针超时，单独复测仍超时，保留原超时和保护规则。最终发行包由版本发布流程另行构建和验收。

## 2026-10-25 0.1.6 地形与建筑导入

- 用 Chunker CLI 将 Java 来源复制到工具箱任务目录后转换；来源、目标备份、分块数据、预览和撤销记录与原地图分离。
- 地形导入按角点读取方块状态、方块实体和含水信息，固定目标实际维度，写入前比较目标并逐批读回；支持覆盖、保留目标非空气和来源空气选项。
- 目标存档完整备份、写前日志和中断恢复保护保留；任务异常不自动重放，支持本次批次撤销。
- UI 改为四步向导，增加选区校验、预览统计、进度、确认弹窗、备份目录入口和深浅主题布局。
- 验证边界：新增模型/快照/Python 运行时测试，Electron UI 真实 IPC 验证；3.10.0.436581 实机使用 Java Anvil fixture、Chunker CLI、负坐标、目标自定义维度、状态方块、箱子方块实体、覆盖/保留和撤销。含水方块在当前 SDK 中可能只能保留方块状态，UI 和任务记录会提示；自定义维度由目标模组负责注册和持久化。

## 2026-10-24 授权成员版本更新

- 设置页增加私有 GitHub Release 更新面板：成员通过 GitHub 授权后检查版本、查看 Release 说明、下载 ZIP 并校验 SHA-256。
- 下载完成后由独立更新脚本在旧程序退出后替换程序目录并重启；用户数据、存档、日志和模组目录不参与替换。
- 设置页提供分页历史、手动检查和启动/运行期间的自动提示；区分没有正式发布、仓库无权访问、授权失效和网络错误。
- 公开 OAuth App Client ID 随源码同步，构建不依赖本机遗留配置。版本标签触发 Actions 构建、测试和草稿资产上传，完整资产就绪后再正式发布；客户端不包含维护者凭据。
- 更新脚本重新校验 ZIP、版本和路径，同盘暂存并保留唯一旧版备份；下载重定向不转发授权头，后台检查不打断下载和安装计划。
- 新增服务、Windows 安装和真实 IPC/UI 的专项测试；网络夹具验收与真实 GitHub 发布、最终发行包验收分别进行。
- 云端验收发现 Windows runner 短 TEMP 路径与 PowerShell 模块环境差异：规范化工作流临时目录，使用 .NET 完成 ZIP 校验，保留产品原有路径保护。Electron 资产下载通过 ClientRequest 处理手动重定向，独立实际网络测试验证取消和响应流。
- 完整升级验收发现早期 Windows 更新启动器的生命周期缺陷：增加独立无窗口启动器、准备回执、失败保留与替换前取消，不再仅凭子进程创建成功就退出客户端。早期版本需先解压打开 0.1.3 完整包一次。
- 安装完成与失败恢复后正常显示客户端窗口；完整验收包含自动重启后的窗口可见性，避免仅凭进程存在判断升级成功。新增跨客户端退出的启动器回归测试。
