## 长期架构节点

- 业务域整理：renderer、shared、Electron domains、native、scripts 和 tests 已按职责分层；详见[架构说明](架构说明.md)。
- 存档生命周期：快速测试、来源快照、配置 revision、存档回收恢复和按最新配置重启由同一套服务状态机管理。
- 多客户端边界：主机、来宾、sessionId、generation、引擎指纹、源码来源和独立数据目录必须分别核对；本机多人默认使用存档房主加定向来宾。
- AI 自动化：MCP 通过 stdio/本机鉴权接口进入现有服务，工具按客户端、配置/存档、地形/维度和观察/拍摄分组；详细 schema 见 [AI 自动化接口](AI自动化.md)。
- UI 文档：通用界面规则见 [UI 视觉重构](UI视觉重构.md)，UI 编辑器和官方引擎限制分别见 [UI_EDITOR_STATUS](UI_EDITOR_STATUS.md) 与 [EDITOR_ENGINE](EDITOR_ENGINE.md)。

提交历史中的 `release: 0.1.x` 提交正文与对应 Release Notes 保持同源，便于从 Git、GitHub Release 和软件更新页查看同一版本信息。
