大果喵游戏工具箱 · 免安装分发版

一、运行要求
本包为 Windows x64 程序，已在 Windows 11 x64 上验证。
工具箱已包含 Electron、MCDK 和所需辅助运行库，日常使用无需安装 Node.js、Python、VS Code 或 npm 依赖。
游戏本体、模组和存档不包含在本包中。对方需要自行准备网易我的世界开发环境及开发版游戏程序。
已验证的开发版为 3.10.0.420447、3.10.0.436581、3.10.0.448891；“联机房间”的邀请加入和 AI 自动入房适配这三个构建，房主和朋友必须使用同一构建，其他版本会拒绝该功能。普通功能在其他版本上的兼容性需要另行确认。

二、首次使用
1. 将整个 ZIP 解压到可写目录，不要在压缩包里直接运行，也不要只复制 EXE。
2. 双击 DaGuoNeko-Game-Toolkit.exe。
3. 打开“设置 → 默认游戏程序”。可直接选择本机开发版 Minecraft.Windows.exe，也可点击“选择安装目录”选择 MCStudioDownload；工具箱会按固定目录结构自动查找版本，找到一个会自动选择，找到多个可在“发现结果”中选择。版本筛选可按自动联机或普通启动用途切换，并展开查看能力表；启动配置也可固定自己的版本。实际 EXE 指纹决定能力，目录名相同不代表构建相同。
4. 在“模组库”添加自己的模组文件夹，在“启动配置”中新建配置、设置玩家名字并勾选模组。
5. 在首页新建存档，或拖入存档文件夹/ZIP；给存档选择启动配置后启动。配套地图自带的行为包、资源包按原清单自动加载，无需逐个添加；建议使用不含额外业务模组的配置，避免脚本冲突。
6. 本机多人测试点击“启动联机客户端”，选择已进入世界的主存档并填写不同玩家名；也可在存档控制台点击“加入此存档测试”。可同时给多个主存档分别添加来宾，日志卡片显示目标和入房验证状态。普通手动联机仍可使用“启动空白客户端”。
7. 内置 MCDK 配合开发版 3.10.0.436581、3.10.0.448891 时，定向加入的来宾也有独立运行目录与下载缓存，可分别测试同 UUID、同脚本名的不同模组；若各组引用相同源码目录，修改源码仍会影响它们。本机流程不需要邀请码、樱花或虚拟网络。来宾锁定房主启动时的实际构建，切换全局版本不会让来宾改用其他构建。

三、日志与调试
运行日志默认显示“脚本日志 → 全部”，可直接查看 print、Python 和 MCDK 输出。
点击“游戏调试日志”后默认显示重要日志（警告/错误），相同问题合并并显示重复次数；普通内容信息和引擎日志可在日志类型菜单中选择。
要接收原版内容日志，请在游戏“设置 → 创作者”开启内容日志文件，或在工具箱“游戏设置”中保存该项启动覆盖。
顶部搜索会检索所选会话的整份已保存归档，支持高亮、上一条/下一条和分页；Ctrl+F 聚焦搜索，Enter/Shift+Enter 定位。
历史清理只删除工具箱保存的日志副本，不删除游戏原始日志。永久删除前可以先导出。
调试、热更新和性能采样需要对应客户端的调试连接就绪；普通空白客户端默认不加载业务模组。

四、可选功能
AI MCP：需要另外安装 Node.js 22 或以上版本，在软件“设置 → AI 多客户端 MCP”复制这台电脑的配置，添加到支持 MCP 的 AI 客户端。
官方 Tracy 窗口：需要本机已有 tracy-profiler.exe，可在“Tracy 性能”中选择；分析器本体未随包分发。

五、数据保存与更新
本软件免安装，但配置和数据按当前 Windows 用户保存，不在解压目录里：
配置、日志及运行数据：%LocalAppData%\DaGuoNeko_GameToolkit\
工具箱管理的存档：%AppData%\MinecraftPE_Netease\minecraftWorlds\DaGuoNekoGameToolkit\
独立主机运行环境：%UserProfile%\DgnGameToolkitHosts\（存档仍保存在原登记位置）
内置启动器的包兼容描述与世界运行配置保存在工具箱 runs/<会话>/ 下，原地图的自带包源码保持原位置，游戏进度直接写回地图。已有 .toolbox-packs 会备份清单后恢复包目录；遇到冲突会停止，请勿把其中源码当缓存删除。自定义启动器仍沿用原兼容模式。
复制或转发软件文件夹不会附带你个人的配置、模组、存档和日志。
升级前先保存游戏并退出运行中的游戏会话。若已在“设置 → 工具箱更新”完成 GitHub 授权，可直接检查、下载并重启安装；工具箱会校验 ZIP 后替换程序目录。也可以从项目私有 GitHub Release 手动下载对应 ZIP 和 `.sha256`，完整解压到新的程序目录再打开。不要用空目录覆盖上述用户数据目录；没有项目仓库读取权限的用户不能使用内置更新。
软件正常退出会结束它启动的游戏会话，请先保存游戏进度。
首次 GitHub 授权跨重启和升级复用；启动时及运行期间每 6 小时自动检查，发现新版弹窗提示。设置页提供历史更新说明与“加载更早版本”。没有正式发布与仓库权限不足会分别提示；安装保留程序旁的 .previous-… 备份，确认新版本正常后可自行清理。
0.1.0–0.1.2 的早期更新启动器存在退出后未安装的问题，请先完整解压并打开 0.1.4 或更高版本一次，现有数据和授权沿用。0.1.3 升级后若窗口未出现，再打开一次软件即可。新版安装器准备就绪后才退出客户端，准备失败会保留当前窗口，安装后正常显示客户端。
内置 MCDK 配合开发版 3.10.0.436581、3.10.0.448891 可同时启动不同存档，分别配置和控制；同一存档禁止重复打开。每个主机独立部署模组与游戏设置，控制台可切换，停止操作只作用于选中的主机。“设置 → 存档主机”可关闭独立模式，其他版本/自定义启动器沿用兼容单主机方式。无法多开时会报告具体原因；已有共享兼容模式的存档需先保存退出后重开，运行中改设置不会升级该进程的隔离方式。
AI 应使用工具箱 MCP 的 launch_world / list_clients，并按 sessionId 和 generation 分别执行代码、热更新、查日志和停止。共用源码不会自动复制，多个配置引用相同目录时会提示；需要独立修改代码时使用不同目录或工作副本。

六、分发说明
存档卡片和控制台的“快速测试”可直接勾选全局模组库中的模组并启动，无需新建配置。使用默认启动参数及已保存的全局游戏程序、窗口大小和按键；每个存档记住上次选择，保留地图进度、自带模组及原绑定配置。选择的模组默认开启脚本热更新，开发辅助模组自动加载。原启动配置已移除时也可使用快速测试；其他页面的未保存草稿不会自动保存。
游戏标题自动显示“Minecraft · 地图名 · 玩家名”，主菜单显示“Minecraft · 主菜单 · 玩家名”。就绪后读取实际名称，标题被游戏重写时后台会同步；无法读取名称的已入房客户端显示“Minecraft · 联机游戏 · 玩家名”。不改变窗口尺寸、位置或焦点。固定保留 Minecraft 前缀，以兼容 MCDK 窗口定位。
“设置 → 默认游戏窗口大小”提供常用尺寸和自定义宽高，初始为 1280×720，保存后用于下次启动；关闭可使用游戏原有尺寸。启动配置单独指定的尺寸优先，自动入房测试客户端继承房主本次启动尺寸。不会改变已运行窗口或改写配置模板。
本机多人测试使用“存档房主 + 多开客户端”：AI 先核对或启动目标存档，再用 launch_joined_client 指定 hostSessionId 加入，直到 autoJoin.phase=joined 才开始测试。每位玩家使用不同名字，每次新增客户端使用不同 requestId；同一次启动的重试复用原 ID。本机测试不使用“联机房间”页，不配置邀请码、隧道或虚拟网络；该页面用于异地朋友加入。
独立主机运行时，可删除、恢复或永久删除其他未运行存档，运行中的目标仍禁止删除。菜单/共享模式或无法确认归属的外部游戏仍需退出后再管理。启动配置已移除时，存档卡片会提示并提供“选择启动配置”；停止会话后控制台立即刷新，仍可切换到其他运行主机。
联机房间首次使用时需要联网下载并校验官方 EasyTier 组件，并接受 Windows 网络助手授权。房主需另行运行樱花 TCP 隧道；双方使用新版工具箱和相同版本的游戏。朋友只需填写邀请文本和玩家名；使用全局游戏程序创建临时联机客户端，不读取本地启动配置，由游戏原生协商世界所需的包。如游戏提示资源包，请选择“下载并加入”。当前为实验验证阶段，入房等待约 120 秒，网络连通不等于游戏入房成功；已用独立标准用户与空缓存验证 customNPC＋大果喵前置的脚本、贴图、模型及 UI 原生下载和实际运行；其他模组、大包慢速下载和两台异地电脑的实际游戏效果仍需验证。
可将此完整 ZIP 发给其他使用者。不要单独发送 EXE，resources、locales 及同目录的运行文件都需要保留。
第三方许可证与来源说明在 resources\licenses\，Electron/Chromium 的许可证也保留在程序目录。
本包未进行数字签名；发行文件的 SHA-256 校验值在 ZIP 旁的 .sha256 文件中，包内 SHA256SUMS.txt 可用于逐文件核对。
版本与打包时间见 release-info.json。
地图预览左侧“选择当前存档”列出当前项目已登记且可用的存档；右侧“选择外部地图”展开“文件夹”和“ZIP / MCWORLD”，支持世界文件夹、.zip、.mcworld。切换来源后自动加载，取消选择保留当前地图；此操作只读，不导入或修改原地图。

七、两台电脑公网联机测试

双方先准备
1. 使用 Windows x64，完整解压同一份最新版 ZIP。房主保存游戏、退出旧工具箱，再从新解压目录启动；朋友首次使用直接打开包内 EXE。
2. 各自准备同一构建的网易 PC 开发版，本次新版联机测试使用 3.10.0.436581，在“设置 → 全局游戏程序”选择各自电脑上的 Minecraft.Windows.exe。两台电脑的安装路径可以不同。不要选择普通启动器、国际版或其他构建。
3. 首次联机需要联网下载 EasyTier 组件；创建或连接虚拟网络时允许工具箱网络助手的 Windows 管理员授权。完整保留自动下载的 DLL，尤其不要单独删除 Packet.dll。

房主操作
1. 在“模组库”收录实际使用的模组，在“启动配置”中启用所需模组和前置；给房主设置玩家名，例如 MapHost。
2. 新建一个测试存档，或导入待测试地图的副本，并绑定上述启动配置。首次异地验证可先只启用 customNPC 和大果喵前置，已完成这组模组的本机独立用户下载实测。
3. 打开樱花客户端，确认有一个可用的 TCP 隧道：本地 IP 为 127.0.0.1，本地端口为 11010。记录隧道提供的公网主机和端口；保持该隧道在线。公网端口与本地端口可以不同。
4. 打开工具箱“联机房间”，选择该存档，把樱花提供的“公网主机:端口”填入“樱花公网入口”，把 11010 填入“樱花隧道本地端口”。若你的隧道使用其他本地端口，两处必须一致。
5. 点击“创建联机房间”，处理 Windows 授权，等待房主游戏进入世界、工具箱显示“等待朋友加入”。已经运行的同一存档可直接共享。游戏应允许多人/局域网联机。
6. 填写“自定义邀请码”创建后，点击“复制固定邀请”，把完整 DGNROOM2: 文本发给朋友。固定邀请不限时，朋友可共用；重新创建时使用原邀请码。自定义短码不能独立定位公网房主，首次仍需粘贴完整邀请。更换邀请码并重新创建会使旧邀请失效；樱花公网地址/端口变化需重新分享一次。无需发送樱花账户或手动发送业务模组。
7. 测试期间保持双方工具箱和房主樱花隧道运行。房主重载世界，或保存后退出并重新启动同一存档，朋友客户端会保持打开、等待恢复并自动重新加入，不需要重发原邀请；重连后自动恢复脚本同步。恢复其他地图或不同游戏版本不会自动接入。
8. 自动重连要求双方使用本包、原邀请码未更换。固定邀请不限时，关闭分享或工具箱后再次创建可复用。朋友退出后可用已保存的邀请和名字再次加入。旧 DGNROOM1 邀请仍按旧有效期处理。遇到断言、原生菜单未就绪或结果不明，会保留朋友客户端，检查提示后可点“重试重连”。新增/删除脚本文件、变更包版本的更新边界不变。

朋友操作
1. 完成上面的全局游戏程序设置即可，无需新建或选择启动配置，也不需要复制房主电脑上的目录、配置或存档。
2. 直接打开“联机房间 → 邀请加入”，粘贴完整邀请，填写与房主及其他玩家不同的名字，例如 MapGuest。输入会自动加密保存到本机，加入后不清空；下次直接加入，也可点“清除已保存的加入信息”。
3. 点击“加入朋友房间”，处理首次组件下载和 Windows 网络助手授权。工具箱会启动自己的客户端并尝试自动加入，不需要提前打开空白客户端或手动添加服务器地址。
4. 如果游戏询问资源包，选择“下载并加入”。本次启动不加载本地业务模组，世界所需行为包/资源包由游戏原生协商下载；已保存的本地配置不改动。朋友无需安装或登录樱花。
5. 等待工具箱显示“已进入游戏”，并在房主游戏里确认能看到该玩家；仅“虚拟网络已启动”不能证明已经入房成功。

进入后怎么验收
1. 双方互相移动、放置/破坏一个测试方块，确认对方及时看到变化。
2. 朋友检查 NPC 模型、贴图和实际模组界面；共同制作地图时，由房主在游戏里给朋友所需的操作员权限。管理界面提示无权限不等于模组没下载。
3. 用一个可恢复的测试设置验证朋友操作→房主回读→重新打开界面仍保留，并在测试后恢复。
4. 地图由房主持有和保存；原生下载不等于朋友拥有可编辑的完整模组工程，也不会自动合并两人的源码修改。
5. 双方用本包启动并加入后，可同步热更新已有 Python 脚本。房主在存档绑定配置中开启“自动热更新 Python 模组”，编辑实际存档 .toolbox-packs 内代码并保存；朋友会自动接收、校验并热更新，无需退房重进。房间页面显示本机状态和朋友的更新回执。
6. 目前同步 Python 文件，不同步 UI JSON、贴图、模型或包清单；不自动重跑初始化。新增/删除脚本文件或变更包版本仍需重新创建房间并加入。单文件最多 2 MiB、总 Python 源码最多 64 MiB、单次最多 256 个变化文件。语法错误会显示失败并保留原文件；修正后再次保存即可继续。传输成功不等于所有业务功能都已验证，仍需检查实际玩法。
7. 来宾更新仅写入当前原生下载包，不修改来宾配置或本地模组工程；这是房主到朋友的单向同步。旧版工具箱没有此功能，双方都应换用本包。已通过同机独立 Windows 用户、冷缓存、房主目录拒绝访问的真实双客户端验证，尚未代替异地两机测试。

失败或结束时
1. 保留“联机房间”的阶段/错误截图。两端到“运行日志”选择本次会话，分别导出脚本日志和游戏调试日志；同时记录游戏构建版本、失败时间及房主樱花隧道是否在线。不要发送包含登录密钥的整份樱花配置或整份工具箱数据目录。
2. 提示游戏版本不同：核对两端选择的实际 EXE 为同一构建（支持 3.10.0.420447、3.10.0.436581、3.10.0.448891）。提示房主工具箱不支持原生下载：房主退出旧版本，用本包重新创建房间。
3. 无法联系房主：先核对房主隧道在线、TCP 类型、本地 IP/端口及工具箱填写的公网入口。网络已连接但找不到房间或入房超时，仍需核对游戏多人设置及两端日志，不要把它当作模组已成功下载。
4. 当前入房等待约 120 秒，大体积资源包或较慢网络可能超时；第一次异地测试先用较小的模组组合定位问题。
5. 加入失败后，朋友点击“离开房间”清理本次客户端；确认房主仍使用相同邀请码和公网入口，再用已保存邀请重试。遇到游戏断言弹窗，应处理并保存错误原文，不要连续创建客户端。
6. 正常结束前先完成游戏内操作并保存进度。朋友“离开房间”会停止本次来宾客户端；房主“关闭联机分享”会关闭本次网络，固定邀请保留，房主游戏继续运行，可随后保存退出。
7. 清理失败后可以再次点击“离开房间”重试；已结束的客户端和已清理的网络不会重复停止。工具箱会区分客户端、菜单与网络清理错误，真实失败不会直接当作离开成功。

验证范围：已通过本机独立 Windows 标准用户、空原生缓存和房主目录访问拒绝的实测，customNPC＋大果喵前置的脚本、贴图、模型和 UI 能原生下载加载，并完成实际设置保存回读。两台独立网络电脑的持续联机仍是本次要验证的内容。

八、地图自带模组
导入时默认选择“自动匹配（存档自带模组）”：自动创建并绑定一套独立配置，继承全局游戏程序、不带入其他配置中的额外模组；之后可以编辑这套配置。也可以直接选择已有配置。
点击“前去添加配置”可新建自己的配置，已选地图路径和名称会保留；配置完成后点击“返回导入存档”，继续导入并使用新配置。
导入文件夹默认“直接使用原目录”：游戏直接读写这份存档，进度保存到原目录。也可选“复制导入（独立副本）”；ZIP 会解压到存档库，原 ZIP 保留。旧版已经导入的副本不会自动转换，需重新选择原目录并使用直接模式。
首次启动会在实际使用的存档内兼容 pack_manifest.json，并将自带包整理到 .toolbox-packs 目录统一加载；直接模式会整理所选原目录，复制模式仅整理副本。此后点击存档卡片“打开目录”，修改 .toolbox-packs 内的代码和资源，无需反复导入。未启用的包不自动开启；额外模组的 UUID 冲突、缺包或版本不符会明确提示。
自带模组已接入热更新：在对应启动配置开启“自动热更新 Python 模组”（自动匹配新配置默认开启），用新版工具箱启动游戏后，保存已加载的 Python 脚本即可自动更新，不用反复退出游戏。关闭自动更新时可点击日志/调试页“热更新脚本”。已有配置的开关保持不变。JSON UI 等资源遵循各自开关；新增模组入口或需要重新执行初始化时仍需重载。旧版正在运行的游戏需先通过新版重新启动一次。
原目录模式移入回收站或清空登记，只移除卡片和运行入口，原存档、进度与模组保留。原路径被移动或删除时会阻止启动，恢复原路径后可再使用；禁止对原目录模式重建世界。复制导入及新建存档仍按原有回收站规则处理。
退出重进后仍按原清单加载，不要求把内置包手动加入模组库。复制、回收或再次导入时保留完整存档目录，包括 .toolbox-packs。若旧版已经覆盖地图加载清单，请从原始地图重新导入。
自动加载不等于所有旧模组都兼容当前游戏。材质断言、资源格式和业务脚本错误仍需要按具体地图处理；工具箱不会自动忽略游戏断言或改写原地图脚本。

九、设置群系
进入存档“功能配置 / 打开控制台”，可点击即时“设置群系”，或“添加功能 → 设置群系”保存常用按钮。选择下拉群系，其他群系可填写已加载的标识符。
范围支持当前区块（16×16）、圆形半径（0–32 方块）、矩形 X 长度 / Z 宽度（各 1–64 方块）。中心为执行时房主脚下方块，矩形沿世界 X/Z 轴，偶数边长向负方向多一格。自动读取当前维度 ID，支持自定义维度。
高度默认整列，按当前维度实际上下界设置；也可填写绝对最低/最高 Y。修改前检查群系存在且范围已加载；执行记录显示维度、中心、高度和已确认列数。失败或断线不自动重试，请先查看实际结果。
群系修改不会重新生成地形。旧 2D 群系会影响整列，3D 表面群系可能按引擎规则影响上方；视觉颜色可能需重新进入区域后刷新。
工具箱不再额外保存或自动恢复群系，旧记录也不再读取或回放；游戏自身正常保存不变。3.10.0.436581 实测只改群系可能在重进后还原，同一区块存在实际方块变化时可以保留。请保存退出后核对结果；工具箱不会为触发保存而额外修改地形。


重载与配置来源：热更新脚本、重载游戏和重载资源沿用本次启动来源，不会自动切到其他 Git 工作树。运行日志、游戏调试和存档控制台可查看实际模组目录；工具箱按钮及 MCP reload_client 在执行前核对已保存配置。模组路径、启用列表或脚本热更新设置变化时会提示并阻止旧快照重载，存档主机可点“按最新配置重启”。请先保存游戏进度，勾选确认后只停止目标主机，并重新读取已保存配置启动同一存档；其他主机保留。快速测试按该存档已保存的勾选列表重启。确认期间配置再次变化、路径缺失或停止失败会中止，不自动回退旧来源。未保存的配置草稿不应用；游戏内原生重载快捷键仍沿用原生路径，不会重读工具箱配置。
